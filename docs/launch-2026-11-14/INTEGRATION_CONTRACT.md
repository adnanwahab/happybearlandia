# Civic/HBL integration contract

Existing `hbl-law-behavior-receipt.v1` and POST `/api/law-behavior` remain the model-data authority. Request lawId, seed, population and implementationStrength only; bounded12 synthetic actors/100 checkpoints; no screenshot/iframe/HTML data extraction, private journal or ballot identity. The server chooses720 population minutes or12 city months; both branches use one synthetic initial state and seed. Literal edited legal text is never compiled implicitly.

Public navigation schema: `civicContext=1`, optional bounded proposalId, integer revision1..1,000,000, lawId21/22/23/83, strength0/.25/.5/.75/1 (law21fixed1), seeduint32, population24, optional bounded modelVersion. URLs use fixed HBL and Civic origins. Unknown fields are dropped; duplicate recognized keys and invalid values fail closed. Context is a synthetic discussion recipe, not a saved legal revision or ballot. Model-version mismatch reports unavailable replay rather than presenting a replacement as equivalent.

On valid import HBL's law panel deliberately uses the API's default synthetic initial world and exact horizon rather than unrelated mapped ConstitutionCity state. On rerun, edited strength changes revision and preserves seed/baseline; the result's modelVersion is returned to Civic. Recorded actor samples are never interpolated into invented positions or stories. Current-year/five-year ConstitutionCity comparisons remain separate.

API timeout:30seconds,504 retryable response and cooperative abort; active comparison slot released in finally. Civic additionally owns UI cancellation/deadline and validates request identity against receipt. Rate limits, origin allowlists and three-comparison cap remain enforced. Exact HBL origin must be in Civic CSP. Local transport proof does not establish production CSP/CORS/deployment parity.

# HBL ↔ Civic Synthesis integration contract

## Intended handoff

The merged HBL PR #316 defines a read-only `hbl-law-behavior-receipt.v1` response from `POST /api/law-behavior`. Civic PR #120 consumes that versioned receipt in native React controls. The HBL receipt is generated by a bounded, separate synthetic law sandbox; it is not a result from compiling Civic's frozen policy plan or arbitrary legal prose.

The merged PR descriptions specify a maximum of 100 sampled checkpoints, at most 12 fixed-index synthetic actor samples, identical seed/horizon for the paired branches, and an explicit allowlist of returned fields. The HBL side describes origin allowlisting, numeric bounds, per-IP/global admission limits, and a maximum of three concurrent comparisons. No full city state, private journals, vote data, real-person IDs, or credentials belong in the response.

## Required consumer behavior

- Send only the supported mechanism and bounded parameter values. Law IDs 22, 23, and 83 use reviewed numeric controls; law 21 is fixed/discrete. Unsupported mechanisms must remain unavailable with a reason.
- Verify the response version and all seed, model, clock/horizon, start-state, branch, actor, and metric invariants before rendering. A mismatch is an error, not a comparison.
- Keep the original 100% reference when a supported strength is edited. Abort or discard stale requests when the user edits again or leaves the view.
- Render only returned observations. Missing actor fields remain unavailable; no inferred movement, individual identity, or causal claim may be added.
- Label the result synthetic, uncalibrated, and advisory. Keep proposal text and votes separate from the model receipt.
- Keep URLs free of access tokens, private journals, ballot identities, and emails. Do not turn advisory votes into activation, approval, or merge authority.

## Deployment and acceptance dependency

Deploy/verify the HBL API before deploying the Civic consumer. PR #316 and Civic PR #120 are merged on GitHub, but production `/synth` was observed without the native viewer and reported `Build unknown`; therefore the contract has **not** been accepted end to end. No live API request was made in this audit. A successful local test or PR merge is not production acceptance.

## Versioning follow-up

Bind each result and shareable context to an explicit proposal ID/revision, mechanism ID, parameter key/value/unit, seed, model/rules version, and horizon only after both repositories implement and validate that mapping. Until then, show the reviewed mechanism sandbox as separate from the frozen legal plan. Version changes require an explicit compatibility or unavailable state.

## Behavior and contract

Entry: `/world/invention/` → Neighborhood Blueprint. Native form controls select
up to nine compatible City catalog policies and three parcel cosmetic palettes.
Export is downloadable JSON plus copyable text (also usable without object URLs).
Import validates the entire payload, shows its replacement policies, source,
horizon, model and cosmetics, and requires explicit confirmation. Changing JSON
invalidates confirmation. Confirmation validates again and replaces a design;
it cannot stack repeated policy edits. Export after a design change requires a
new click, avoiding a stale download presented as current.

Strict schema pins blueprint/model/scenario versions, synthetic month-2 source,
seed, 1–36 months and locale-neutral unit tokens. It rejects unknown fields,
unsupported parcels/mappings/versions/units, conflicting scopes, duplicate
cosmetics, invalid JSON, nonnumeric settings and payloads over 8192 UTF-8 bytes.
Policy amount/cost semantics remain in the existing versioned catalog; no import
can supply arbitrary costs or directly mutate parcels. No implicit migration,
partial import or guessing geographic equivalence.

Compatibility is deliberately limited to the synthetic Riverside fixture's
`parcel-d0`, `parcel-d1`, `parcel-d2` and matching district identities. Tests
compare these IDs to actual source checkpoints at three boundary/example seeds.
There is no compatible adapter for arbitrary saved worlds. Reload loses the
session; exported JSON is the portable persistence mechanism. Cosmetic swatches
are retained in JSON and excluded from the policy replay URL. No 3D visual
makeover or cross-model mapping is claimed.

A local synthetic fixture using the existing `buildTown` Houston test origin,
20 people, `recordHistory:true`, default model seeds and 180 modeled steps
produced 13 generated parks and 122 retained trip start/completion records.
Coverage was minutes 360–540 with zero dropped event records. Trip fields included
`destinationId`, `personId`, `minute`, `mode`, duration/distance and route kind;
none contained position, coordinate, origin or trajectory fields. These are
synthetic test outputs, not observed street life or a new fixture location.

**Decision:** do not label current moving residents, decorative traffic/wildlife,
or reconstructed straight lines as a recorded minute. A narrower static ambient
view plus recorded destination-event highlights is technically feasible without
trajectory recording, but must explicitly say “trips to this park,” not claim
passersby were nearby. It would not establish animated historical playback.
This audit leaves that distinction explicit rather than shipping a misleading
camera-only substitute. No social rules, scheduler, retention or ODD changes
were made; existing descriptions remain applicable.

## Next integrated slice and acceptance tasks

1. Establish a versioned read-only observation manifest for one authority:
   run/model/rules versions, seeds, retained town/geometry identity, park ID,
   modeled interval, event IDs, coverage/evictions and source classification.
   Define 60 presentation seconds separately from modeled minutes. First support
   exact park destination events; exclude unmapped actors and unsupported sources.
2. Add a park anchor selector that validates finite, simple supported polygons,
   proves the camera point lies inside with clearance, and checks loaded solids.
   Treat offsets as presentation assumptions, never surveyed bench coordinates.
   Unsupported/missing/obstructed geometry must explain failure without moving.
3. Integrate normal `/world` entry, exclusive camera ownership and an observation
   panel with recorded highlights. For historical animated street playback, first
   retain bounded committed scene frames with source identities/time; never
   interpolate from today's actor positions. Do not modify the active authority
   or generate events to fill quiet intervals. Empty/lost coverage stays explicit.
4. Capture camera/control state and restore controls immediately on Exit/Escape,
   source reset, navigation or failure. Ignore late asynchronous reads. Recheck
   camera safety on return; never trap the player if the previous pose is occupied.
   Low-power mode must actually stop observation animation and show a detached
   static ambient scene; a fixed camera over a still-running renderer is insufficient.
5. Verify normal route success, no park, malformed geometry, empty/truncated
   history, source reset and rejected read; rapid enter/exit and teardown; model
   immutability and deterministic record selection. Browser checks must cover
   390px touch controls, keyboard focus/return, visible focus, reduced motion,
   static low-power rendering and immediate exit during loading/playback.
   Instrument host frame pacing plus overlay update cost, listener/resource
   counts and post-exit cleanup; avoid a second animation loop. Record actual
   measurements and hardware limits without claiming headless timing is device acceptance.

This can be implemented locally; there is no required production service or
outreach. Historical scene retention is an application/data-contract prerequisite,
not an external provider outage. Human review must resolve the delivered playback
scope and inspect the eventual desktop/mobile evidence. Real-device performance
remains a hardware prerequisite. No implementation delegation was justified for
this dependency audit.

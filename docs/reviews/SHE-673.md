## Required next slice

Implementing a success path now would require inventing a service authority or
mislabeling passenger trips. Preserve the issue's prohibition on guessed schedules.
Before implementing the panel, establish a versioned, model-owned read contract
with stop IDs and supplied coordinates, route/vehicle/service/trip IDs, run and
rules identity, model date/clock units and retained arrival-event references.
Document which records can support a next arrival at the selected run time and
which are only planned. Define retention, unavailable, malformed, stale-run and
missing-trip behavior. Do not bridge authorities using coincident IDs or times.

Then implement one World stop selection through its normal picker and an
accessible panel, using only that read contract. Clicking an arrival must open
the associated retained trip in the same run. Unknown schedules must remain
unknown; missing trip evidence must not produce an invented link. Verify:

- successful recorded service and exact trip navigation;
- unsupported stops/vehicles, absent records, invalid data and read failure;
- run/time changes, deterministic read replay, stable identities and no mutation;
- mobile touch controls, keyboard opening/dismissal and visible/restored focus;
- immediate reduced-motion operation, bounded overlay updates, frame-pacing
  measurements and disposal of listeners/resources on close and page departure.

These are proposed prerequisites and acceptance work, not a new implemented schema.
No external provider, live predictions or production configuration is required to
invent missing evidence. A reviewed local model/service-record implementation is
the prerequisite. Hardware frame-pacing and mobile checks remain outstanding.

## Contract and behavior

`tripFireflies(populationSnapshot, cap)` returns `population-fireflies.v1`. Inputs use the existing Population snapshot's runtime ID/revision, minute (modeled minutes), effectiveConfig.seed, modelVersion, metrics.activeTrips and visibleAgents. At most 2,000 supplied rows are examined, then a stable lexicographic source-key order is capped to 160 particles. A key is the JSON tuple [runtime.id, runtime.revision, personId, departureMinute], identifying a current committed departure in its authority/revision; it is not a durable completed-trip event ID. The receipt keeps these pins plus route/rules version. Each marker opens the existing Population resident inspector and displays that current trip receipt. Receipt clears on a new snapshot.

Only positive-remaining `population-current-trip.v1` rows with finite [0,1] progress and `mapped-sidewalk` / `sidewalks.v1` routes qualify. Ordered finite world-metre x/z points must have positive length matching distanceMetres within max(0.01m, length * 1e-6). Fallbacks, unknown versions, malformed geometry, duplicate actor IDs and missing trips produce no marker. No connector or route is invented. Missing model totals stay unavailable; zero is a supported numeric total. Active trips include all purposes, not just work commuting. This label does not imply completed journeys in an evening interval.

`samplingWeight` is explicitly null: the worker prioritizes travelers near the camera and may force a selected resident into its sample; inclusion probabilities are unavailable. `representationWeight` retains a positive supplied row.weight or null, and is not an inverse sampling weight. No extrapolated trip or population estimate is made. The displayed rendered sample is the capped marker set (offscreen markers are culled); model-wide activeTrips comes independently from the existing model metric. This is a nonprobability display sample, not statistically representative evidence.

Source observations: none introduced. Existing geography may be sourced; sidewalk construction and access are model assumptions, not surveyed route validation. Trips/progress are computed synthetic model records. Gold radial glow is purely decorative. No glow count, brightness or size encodes probability, causation or population. The authored seed-42 fixture is representative of the interface only: 1,200 active model trips, 200 eligible supplied rows and 160 displayed markers; it is not an observed commute dataset.

Normal entry: `/world?living=1`, World controls → advanced controls → Commuter fireflies → Show sampled journeys. The control remains off initially. Legacy World/missing snapshots show unavailable and no particles. The standalone Canvas2D fallback is unsupported. Positions use committed route progress and never wall-clock animation or model RNG. Identical snapshots/replays yield identical source order/positions; pause holds progress. Same seed alone cannot reproduce a changed camera-selected sample or changed model inputs/versions. Markers are native labeled buttons, with no additional animation loop or GPU resource. Existing frame callback updates projection; pagehide releases DOM/listeners and references. Overlay diagnostics expose max update cost/frame interval, counts and disposal state; these are CPU diagnostics, not GPU measurements.

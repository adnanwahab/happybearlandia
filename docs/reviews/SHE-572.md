## Decision and next integrated slice

Do not invent a seed/checkpoint for authored arithmetic or silently replace a
mission with a fresh City scenario. An asynchronous clarification asks whether
the relay should use the existing frozen City contract on this page or version
the six authored missions separately. No answer was available at writing.

Recommended path if monthly City is intended:

1. Expose a separate City challenge entry on `/world/challenges.html`. Reuse
   `city-challenge.v1`; retain authored mission/family state independently. Show
   synthetic classification, initial hash/month, seed, engine version, reference
   action IDs and horizon. Do not imply a mapping to the authored campaign.
2. Define a validated receipt plus replay evidence; incoming receipts open
   read-only. Explicit Fork creates a separate candidate with parent receipt
   identity and only permitted action IDs. Never overwrite reference or accept
   caller-supplied outcomes, seed, state, costs or budget overrides.
3. Test ownership with disposable injected actors/storage. Actual private sharing
   requires authenticated principals, an authoritative private parent loader,
   read/fork authorization, durable child ownership/lineage and retention/access
   policy. These are prerequisites before live activation, not permission to
   enable services. A local self-contained recipe can precede this only under an
   agreed, explicit integrity-only/unauthenticated ownership limitation.
4. Verify clean recipient open → inspect → fork → permitted edit → replay;
   compare source bytes before/after and seed-matched results. Reject unknown or
   duplicate actions, tampering, oversized links, incompatible versions, missing
   sources and stale async validation. Test cancellation and unavailable metrics.
5. Check keyboard focus, announced errors, mobile overflow, reduced motion and
   worker/uncompressed-file fallback on the named route. Capture disposable
   before/after evidence there. Never export recipient localStorage implicitly.

If the six authored missions are intended, first specify/version receipt scope:
mission preview versus full campaign/project schedule/council state. Represent
absence of RNG explicitly rather than inventing a seed. Add the model's ODD
description/inventory entry with that implementation. This is a different model
contract, not a City adapter. No model rules changed in this audit, so existing
ODD descriptions remain unchanged.

## Audit and design

inventory, room adapter and interior, renderer, app, visual styles and shared
media preferences/sound engine plus relevant tests. No docs/architecture.md exists.
GitHub connector open-PR audit found adjacent household PRs #373–376 and
architecture palettes #372, but no open PR matching mood. Existing visual styles
are global; room moods are a separate local preference. Existing source evidence
files under `.mini-symphony-evidence` were preserved.

`room-moods.js` owns version-1 preferences scoped by saved experiment and household
IDs. It accepts only current room IDs and named presets. Browser localStorage is
separate from checkpoints/autosave. Invalid selections reject; corrupt/unavailable
storage falls back to session preferences. Reset clears all room overrides.
`room-moods-ui.js` supplies native selects/dialog/buttons and storage/audio/scene
fallback messages. `app.js` mounts and destroys it through the normal saved-home
path. `house-renderer.js` adds bounded static non-shadow room-anchor point lights,
without postprocessing or animation; identical refreshes reuse existing lights.
`sound-effects.js` exposes existing opt-in, volume-controlled short cue playback.
Cozy/Lively have explicit previews; Quiet/Default are silent. These are authored
cosmetic cues, not modeled resident reactions or continuous ambient soundtracks.

No simulation commands, RNG draws, needs, IDs, versions, clocks, causal records or
saved household data change. ODD inventory remains accurate: this is presentation,
not a new social model. Unit tests compare the complete serialized Population
fixture before/after accepted/rejected preferences (seed 42, eight residents,
household size four, employment rate zero, initial minute/tick 600).

## Mechanism and provenance

Installed Three.js 0.186.0 `src/renderers/common/XRManager.js` supports native
WebGPU only with session `webgpu` enabled and XRGPUBinding. Request requires
`webgpu` and `local-floor`; there is no implicit WebGL fallback. Failure leaves
the existing desktop scene available, with a visible reason and Street view.

The versioned saved-experiment loader and successful checkpoint restore remain
the admission authority. No new model or social-sharing path is introduced.
The scene, entity IDs, geometry, checkpoint inputs, seed and model versions are
reused. Entry pauses the current frame of the restored run, which may have
advanced since loading; it does not rewind or claim to be the original saved
minute. The desktop status retains saved ID, codec, current minute and geometry
source. Model time pauses. Existing save access rules are not expanded. Missing
or denied saved loads never enable walk entry. This is a presentation feature;
no modeled outcome, survey or safe pedestrian routing claim is added.

Road stops are bounded, deterministic samples of loaded road centerlines at
approximately 8m spacing, rejecting points inside supplied building polygons.
This assumes flat ground at y=0. Desktop eye height is an illustrative 1.65m;
XR uses actual local-floor tracking height. Teleport is instantaneous, ray-to-
ground then nearest stop within 4m, with a 20m aiming limit. Snap turn pivots
around the viewer and requires stick release before another turn. No continuous
walking, animated turn, camera following or camera director runs during a walk.
A fixed optional black peripheral mask avoids a motion-triggered fade/flash and
is the same under reduced motion. It does not certify comfort for every player.
Headset buttons provide both turns, comfort toggle and exit through controller
rays; the system session exit remains available. No DOM overlay is required.
Desktop buttons/select provide touch and keyboard alternatives; Escape exits.

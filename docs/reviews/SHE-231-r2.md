## Taxonomy and proposed regressions

Run searches from repository root. Each command locates candidates; trace its callers and tests before treating a match as a defect. For each test, preserve the exact seed, model/rules version, recipe, experiment/arm/run identity and selected time in failure output. Use synthetic fault injection explicitly labeled as such. Existing test files named below are extension points, not claims of missing coverage.

### H01 — competing authorities for selected run and time

**Family:** state synchronization. A panel-local month/run or URL restoration could diverge from the coordinator, producing disagreeing counts and explanations for another frame. `world/future-machine/main.js` already centralizes `setMonth` and publishes UI updates; inspect alternate surfaces for bypasses.

**Search:** `rg -n 'setMonth|onMonth|popstate|setInterval|state.month' world/future-machine world/run-lifecycle-ui.js`. Follow timeline, playback, shared-link and inspector callbacks; identify every independently writable clock.

**Regression design:** through the normal Future Machine page, run a fixed recipe, scrub forward/back, play/pause and reopen its shared URL. At each settled action assert timeline, scene, outcome table, WHY context and URL agree on experiment and month. Extend coordinator/outcome-timeline tests and `test/e2e/future-machine.e2e.js`. A failure implicates authority propagation rather than an individual label.

### H02 — pending configuration presented as completed-run state

**Family:** state synchronization. Editing inputs during a request may let controls display the next recipe while counts or sharing silently refer to the last completed recipe. Retaining previous results is valid only with their own visible identity. The coordinator already passes `comparisonRecipe` separately.

**Search:** `rg -n 'comparisonRecipe|originalRecipe|onConfigure|status|preview' world/future-machine/main.js world/future-machine/ui`. Trace pending, preview, completed and error transitions.

**Regression design:** complete A, submit B, edit C, then fail B. Assert A's counts/provenance remain explicitly A, C remains editable, and exported/shared completed results never claim C. Retry must use the documented failed attempt. Extend `test/e2e/future-machine-race.e2e.js`; use deferred API responses to control ordering.

### H03 — superseded async work commits after cancellation

**Family:** async lifecycle. Abort alone cannot stop an already resolved promise, renderer import or progress callback; a stale completion could overwrite a newer run or re-disable controls. Main already checks request identity and generation counters.

**Search:** `rg -n 'AbortController|request!==current|Generation|then\(|onProgress' world/future-machine/main.js world/future-machine/data`. Trace every await/callback to its commit guard, including errors and sharing.

**Regression design:** submit A then B; deliver B before A, then deliver A progress/error/success after cancel and after navigation. Assert only B updates DOM, URL, share output and history, with no unhandled rejection. Extend race browser coverage and `test/future-machine-boundaries.test.js`. Reverse completion ordering to distinguish a real guard from fortunate timing.

### H04 — unfinished work lacks a terminal user-visible state

**Family:** async lifecycle. A fetch/body/import that never settles may leave provenance loading or dashboard controls busy indefinitely. A warning timeout is different from cancellation and a terminal error. `world/model-provenance-loader.js` already loads definitions independently of graphics and warns after 8.5 seconds; the paired adapter has an operation deadline.

**Search:** `rg -n 'loading|setTimeout|timeoutMs|finally|Promise.all' world/model-provenance-loader.js world/future-machine/data world/future-machine/ui`. Map each operation's deadline, cancellation owner and visible retry path.

**Regression design:** stall response headers, response body and metadata import separately using fake clocks/injected loaders. Assert bounded transition to the documented slow/error state, truthful retained-result labeling, usable recovery controls, and no stale late overwrite. Test the normal page loader separately from the adapter so one timeout cannot mask another surface's indefinite spinner.

### H05 — worker failures strand bookkeeping or release it twice

**Family:** async lifecycle. Constructor, postMessage, message decoding, crash and timeout can bypass different cleanup paths, leaving queue slots occupied and dashboards apparently inert. The existing boundary inventory explicitly distinguishes pool, City worker and geometry cache behavior.

**Search:** `rg -n 'postMessage|messageerror|pending|terminate|timeout' world/workers world/city/worker-call.js world/render/geometry/geometry-cache.js`. Trace allocation-to-settlement and host error presentation, not only rejection handlers.

**Regression design:** inject each boundary fault, then submit a healthy task. Assert one settlement per request, cleared handlers/timers, restored capacity, actionable host status and successful subsequent work. Extend worker-platform/City-worker tests; add geometry-host coverage only after checking existing contracts. Retry only deterministic work with preserved input ownership; no fabricated successful result. Reuse SHE-108 evidence.

### H06 — divergent API envelopes and version negotiation

**Family:** API contracts. One caller may accept a legacy or malformed response that another rejects, turning schema drift into loading or incorrect results. Future Machine already validates manifest, recipe, replay identity and versions.

**Search:** `rg -n 'response.json|modelVersion|scenarioId|runIndex|identity|normalizeReplay' world/future-machine/data world/city server.js`. Compare endpoint producers, adapter validators and UI consumers against `INTERFACES.md`.

**Regression design:** mutate a valid API response one field at a time: wrong experiment, swapped arm, absent version, malformed JSON, and incomplete history. Through create/reopen assert rejection before publication, visible retry guidance and retained previous-run identity. Extend manifest/integrity/boundary tests rather than introducing a parallel schema. Include a supported historical receipt to detect accidental compatibility loss.

### H07 — missing values and unlike denominators collapse into counts

**Family:** API contracts and state synchronization. Null, absent records, represented population and explicit entity rows may all be coerced into numeric zero or compared as equivalent counts. Correct arithmetic can still describe different populations or units.

**Search:** `rg -n '\?\? 0|\|\| 0|population|households|available|missing|unit' world/future-machine/diff world/outcome-analysis.js world/population/DATA_FORMATS.md`. Trace each dashboard number back to its collection, filter, denominator and time.

**Regression design:** remove one arm's measurement, supply an actual zero in the other, and vary resident rows independently of represented population. Assert unavailable stays unavailable, zero stays zero, and every comparable count uses identical scope/time/units. Extend `test/future-machine-diff.test.js` and outcome-analysis tests; do not force unequal metrics to agree by changing labels alone.

### H08 — cache identity omits material run inputs or lifecycle state

**Family:** caching. A recipe-only cache could alias different model versions, seeds, arms or months; retained page caches might restore disposed handlers. Browser asset caching is a separate source of frontend/backend skew.

**Search:** `rg -n 'new Map|cache|localStorage|sessionStorage|Cache-Control|dispose' world server.js docs/static-asset-caching-audit.md`. Enumerate key fields, eviction rules, schema migration and mount/unmount ownership. The paired data README explicitly disclaims a global history cache; do not assume one exists there.

**Regression design:** alternate A/B/A with one input changed at a time (seed, rules version, policy, arm, month), then navigate away/back. Assert correct identity, no shared mutable history, and one working listener per control. Reopen a supported old receipt under fresh assets. Extend storage, City Lab lifecycle and static-asset-cache tests according to the cache actually found.

### H09 — renderer fallback changes model authority or exists only on one route

**Family:** rendering. A capability branch may restart a simulation or restore a default recipe, or callers may assume all routes inherit Future Machine fallback. This could hide real missing rendering while inventing continuity.

**Search:** `rg -n 'createRendererBackend|createCanvasStage|device.lost|contextlost|low.fidelity' world tools/webgpu-demo-runtime.js`. Build a route-to-renderer-to-model ownership matrix from actual entry imports.

**Regression design:** on each supported route, force WebGPU init failure, WebGL failure and mid-session loss separately. For Future Machine assert Canvas or inventory fallback retains exact selected frame, receipt, seed and version; for unsupported routes assert explicit actionable failure, never a substituted forecast. Extend pipeline-device-loss and saved-World fallback journeys. SHE-169 already covers the CPU-history rendering mechanism; GPU-compute recovery requires separate evidence.

### H10 — cleanup failure interrupts recovery or late callbacks resurrect UI

**Family:** rendering and async lifecycle. One throwing dispose can prevent fallback construction, while outstanding animation/import callbacks may allocate after navigation. The shared demo runtime already tests best-effort cleanup; scene hosts need independent contract checks.

**Search:** `rg -n 'dispose\(|releaseScenes|requestAnimationFrame|whenReady|pagehide' world/future-machine/scene tools/webgpu-demo-runtime.js`. Inspect exception boundaries and disposed checks at every asynchronous resource allocation.

**Regression design:** inject a throwing control/material/renderer disposer during loss, dispose during deferred backend import, and notify loss twice. Assert remaining cleanup attempts, one fallback/status, settled readiness, no later canvas or frame callback, and idempotent final disposal. Extend resource/scene tests without treating mocked resources as proof of real GPU memory reclamation.

### H11 — enabled controls are occluded by independent layout owners

**Family:** rendering and accessibility. Fixed navigation, safe-area offsets, overlays and panel stacking may each reserve space locally, causing hit-test interception despite a visually enabled button.

**Search:** `rg -n 'position:|z-index|pointer-events|safe-area|100vh|overflow' world/future-machine/ui/styles.css world/*.css index.html`. Trace actual header/panel styles on affected routes, including expanded guides and error notices.

**Regression design:** open the normal homepage-linked journey at 320, 390 and 768 CSS pixels, with expanded guidance, long error text and zoom. Use elementFromPoint at enabled-control centers, viewport bounds and keyboard activation; assert navigation cannot obscure timeline, retry or sharing. Extend approved-demo-responsive tests. Screenshots supplement hit testing; neither DOM presence nor bounding boxes alone establish usability.

### H12 — disabled semantics omit an accessible reason and recovery

**Family:** accessibility. Availability may be computed in multiple components while explanation lives in a hover-only tooltip, is stale, or is absent from the accessibility tree. Native disabled buttons cannot receive ordinary tab focus.

**Search:** `rg -n 'disabled|aria-disabled|aria-describedby|title=|role=.status|aria-live' world/future-machine/ui world/run-lifecycle-ui.js world/model-provenance-loader.js`. Pair every availability predicate with its visible reason and next action.

**Regression design:** exercise idle, busy, unsupported-backend, validation-error and ready states using keyboard and accessibility-tree inspection. Assert a visible associated explanation and reachable alternative action for each unavailable control; ready controls activate once, and status changes announce without playback chatter. Extend accessibility browser tests plus UI state tests. A tooltip alone is insufficient evidence.

### H13 — provenance metadata depends on renderer readiness or stale global state

**Family:** data provenance. Model definitions and evidence requests may be incorrectly gated on 3D startup, or a global “ready” flag may suppress metadata for a newly selected model. Definitions are assumptions, not the run's causal evidence. The independent metadata loader already addresses part of this family.

**Search:** `rg -n 'hblSimulationModel|simulationModelMetadata|provenance|whenReady|import\(' world/model-provenance-loader.js world/future-machine/ui/provenance.js world/future-machine/story`. Trace ownership and reset rules for metadata versus per-run receipts.

**Regression design:** block graphics while allowing metadata, then block metadata while allowing recorded results; switch run/model before a delayed metadata response resolves. Assert independent status, exact version association, explicit missing evidence and no claim that definitions prove an outcome. Exercise the normal World metadata host and Future Machine provenance panel separately.

### H14 — evidence joins erase causal scope or promote narrative to fact

**Family:** data provenance and simulation identity. Local event IDs can collide across arms/months; nearest-event matching or carried-forward observations can attach a plausible but false WHY explanation. Synthetic assumptions may also be presented as observations.

**Search:** `rg -n 'eventId|policyId|projectId|constructionReceipts|describeSelection|evidence' world/future-machine/evidence.js world/future-machine/story world/city`. Follow exact event→project→policy relationships and scope keys, including absence paths.

**Regression design:** give both arms the same local event ID at different months with different projects, remove one dependency, and select an entity with no event at the current month. Assert the full experiment/arm/run/month/event chain, historical labeling where appropriate, explicit missing links, and no inferred causal claim from narrative proximity. Extend evidence-trail/story tests. Preserve observed, synthetic, modeled and interpreted evidence categories.

### H15 — entity and time identity conflated across models or replay arms

**Family:** simulation identity. Array positions, display names or shared local IDs may stand in for stable scoped identity; City months, Population ticks and household observations are not interchangeable clocks. This can create false entity movement, mismatched outcomes and irreproducible comparisons.

**Search:** `rg -n 'findIndex|householdId|buildingId|runId|scenarioId|tick|month' world/future-machine/integrity.js world/future-machine/scene/mapping.js world/future-machine/ui/household-timeline.js world/population`. Find explicit cross-model identity/time mappings; absence means the join is unsupported, not implicitly valid.

**Regression design:** reorder collections, collide IDs across arms/experiments, delete an entity for one frame and reverse-scrub. Assert stable geometry/selection for surviving exact IDs, absent observations remain absent, and mismatched clocks/seed/version fail closed. Run matched-seed replay at 0, 42 and 4294967295 with unchanged inputs; compare canonical histories. Extend scrub-identity/integrity/paired tests. Require an explicit mapping fixture before testing any City↔Population transition.

## Investigations that can remove whole bug classes

These are proposed priorities, not accepted implementation scope or measured impact:

| Priority | Investigation | Shared invariant / likely reach | Exit evidence |
| --- | --- | --- | --- |
| 1 | H01–H03, H06, H15: trace one run/frame publication boundary | Every displayed result has one validated run identity and time; eliminates stale-result, mixed-arm and split-clock families | Controlled request permutations and malformed identity never publish inconsistent panels |
| 2 | H04–H05, H10: audit settlement and disposal as lifecycle contracts | Every started operation settles or exposes bounded actionable status; every acquired slot/resource has an owner | Fault matrix demonstrates recovery plus a successful next operation, not merely a rejected promise |
| 3 | H07, H13–H14: audit metric and evidence lineage | Counts carry units/denominators; explanations retain exact dependency scope and epistemic category | Missing/colliding evidence remains explicitly unavailable, across all consumers of the shared record |
| 4 | H09: map capability boundaries per normal route | Rendering degradation preserves authority; unsupported recovery is stated truthfully | Route-specific init/loss tests preserve exact records or present an explicit supported exit |
| 5 | H08, H11–H12: audit cache and UI-shell contracts | Cache reuse respects identity/lifecycle; controls remain reachable and explain availability | Key mutation, restored-page and narrow-screen keyboard/hit-test matrices pass |

Map symptom to initial probes: unexplained disabled buttons H02/H04/H12; inert dashboards H01/H03/H05/H08; loading provenance H04/H13; disagreeing counts H01/H06/H07/H15; overlapping navigation H11; absent fallback H09/H10. This mapping is many-to-many and is not causal confirmation.

Avoid fixes that merely change a count, remove disabled styling, hide a spinner, raise a z-index or restart a default simulation. First establish the violated shared invariant and a failing regression. Reuse existing guards where they work; investigate their callers and alternate entry points before replacing infrastructure.

## Next bounded implementation slice

Implement one synthetic, immutable saved-checkpoint journey first. Broader live
geography, continuous simulation synchronization and cross-model navigation stay
outside that first slice. Synthetic scope must be established from validated
source metadata, not merely `?synthetic=1` in an arbitrary URL.

1. Define a versioned presentation-only envelope with an exact allowlist:
   checkpoint reference/version/hash, monotonic message sequence, bounded local
   camera position and target. Reject extra keys, nonfinite/oversized vectors,
   incompatible checkpoint context and stale sequences. Preserve the original
   checkpoint identity and clock; never derive a new run or advance time from a
   camera packet. Read checkpoint metadata through a narrow read-only resolver.
2. Add a separate ephemeral room service using the existing Bun WebSocket
   infrastructure/patterns, with no game/party topic sharing. Provide anonymous
   host/follower capability roles, room/member limits, expiry, same-origin
   upgrade checks, message throttling, slow-client handling and disconnect cleanup.
   Make the initial host departure end the room explicitly to avoid silent
   authority transfer. No persistence, names, account identifiers, coordinates,
   source geometry, labels, or entire checkpoint payloads in room messages.
3. Add opt-in Create/Join/Leave and Stop following controls to `/world`. Opening
   an invite must show a join explanation before connecting. Keep the capability
   in a fragment/manual code rather than copying the current geographic query.
   Explicitly pin the selected immutable checkpoint; missing/mismatched records
   remain unavailable with no fallback simulation. Host selection changes must
   validate a supported checkpoint before publishing; follower consent must
   precede navigation. Leave closes the connection and stops future application.
4. Bind camera changes through a single presentation adapter after checkpoint
   restoration, coordinating the three PR surfaces above. Manual camera control
   stops following. Apply direct camera updates for reduced motion, throttle
   updates, and show an honest unavailable state for Canvas2D until a tested
   mapping exists. Label the synthetic scene and cosmetic camera motion; never
   label shared views as independently verified model results.
5. Verify through the normal World entry point with two disposable browser
   contexts and temporary stores. Capture desktop/mobile before/after evidence
   with no production credentials, provider requests or personal data. Keep any
   service activation local to the test fixture; hosted service enablement is a
   separate operational prerequisite, outside this authorization.

The initial transport can pin one checkpoint, but that alone does **not** satisfy
the issue's selected-checkpoint synchronization acceptance. That behavior needs
its own validated selection transition and test before claiming completion.
Proposed limits and lifecycle decisions above are design recommendations, not
existing implemented behavior or measured performance.

## Acceptance evidence still required

- Happy path: host creates, follower explicitly joins the same supported
  checkpoint, camera and subsequent supported checkpoint selection synchronize,
  and leave/host exit stop updates with clear role/status text.
- Privacy/authority: reject names, origin/lat/lng, arbitrary URLs, extra fields,
  malformed capabilities, follower writes, expired rooms and cross-origin
  upgrades. Prove the source record and its hash are unchanged after the entire
  two-client session; verify no room route can save, fork, mutate or step a run.
- Failure: service unavailable, missing/mismatched checkpoint, disconnect,
  stale/out-of-order packet, flood and slow client. No silent substitute run or
  retained movement after leaving/disposal.
- Accessibility: keyboard-only join/leave/stop-follow, visible focus, labeled
  inputs, focus recovery, polite role/connection announcements without live
  camera-frame announcements, reduced motion, 390px layout and low-end fallback.

## Mounted storage ownership worksheet

`fly.toml` declares one `app` process, `hbl_data` at `/data`. The sole serving
Machine/process owns all configured SQLite and file writes. SQLite WAL locking is
not a replication or cross-Machine ownership protocol. `--ha=false` alone does not
prove the current Machine count: an operator must inspect actual attachments,
processes, Machines, jobs and external writers before proceeding.

| Configured authority | Path | Backup/validation |

| Server logs | `/data/server-logs` | Preserve restricted incident evidence per retention/privacy policy; not a simulation authority |

Inventory other enabled stores (journals, votes, surveys and custom paths) and
explicitly back up or exclude each with owner rationale. Readiness covers World
and Decision only. Future Machine recipe reconstruction and Reality shares are
different contracts. Do not infer checkpoint equivalence or cross-model identities.
Record numeric UID/GID, mode, resolved mount, capacity and attached Machine for each
path privately. The Dockerfile sets no explicit `USER`; do not assume host ownership.
Restore to the approved runtime UID/GID with private directories/files (700/600),
then verify access as that runtime user; never solve access errors with chmod 777.

## Safe staging sequence — preparation only

1. Human operator supplies a distinct staging app/origin, independent volume,
   approved synthetic dataset and permitted actions. Reject production aliases,
   shared volume attachments, production credentials and automatic fallback to
   production environment variables. Do not download live backups for this issue.
   Record current and known-good application digests/builds and matching configs.
2. Establish an approved containment procedure before stopping anything. The app
   has no generic maintenance flag. Block ingress and autostart/restart paths by
   the approved staging method, stop the only writer and verify no background job,
   shell or second Machine can reopen the store. Stopping a Machine while HTTP
   autostart remains active is insufficient evidence of quiescence.
3. Record UTC backup boundary, versions, seeds/provenance and storage inventory.
   Take consistent SQLite snapshots via SQLite backup/VACUUM INTO, not raw copies
   of an open main file without WAL. Preserve original main/WAL/SHM together; never
   delete WAL to force startup. Copy Decision snapshots while all writers remain
   stopped. Keep the complete coordinated backup immutable and independently held.
4. Validate each database's integrity and schema with the matching image; record
   relative files, byte sizes, SHA-256, creation/boundary timestamps, permission
   checks and expected private sample IDs. Hash the transferred copy again. An
   empty or missing required store, mismatched hash or partial backup is a stop.
5. Restore copies into fresh private paths on the separate staging volume. Never
   overwrite the source or modify the only backup. Configure every authoritative
   store explicitly, not just World/Decision. Verify mount and runtime ownership.
6. With no serving writer on those paths, run the known-good image's compatibility
   check against a disposable copy of the current schema. If it fails, forbid
   image-only rollback. Test recovery from the pre-change coordinated backup using
   another fresh path set instead; reconcile writes since its timestamp first.
7. Start exactly one approved staging process using the recovered paths and exact
   immutable image/config. Run `bun ops/release-health.js` inside that environment;
   require both probes, exact build and three spaced readiness checks as specified
   in `docs/release-operations.md`. Read known World and Decision records, the City
   experiment and share, verifying provenance and expected query results. Restart
   the same staging writer under approval and repeat saved-record reads.
8. Record times, actual digests, checksums, query results, build/probe responses,
   ownership evidence and failures without payloads or secrets. Compare measured
   RPO/RTO with accepted objectives. Run the existing offline reviewer with the
   private record; its complete result only permits human review, never execution.
9. On failure, keep traffic contained and stop the recovered writer. Preserve its
   diagnostic state; retain original paths/config/backup. Return to the preserved
   compatible staging image/path set only after compatibility and write ownership
   checks. Do not alternate writers or discard new writes. Human storage owner
   decides reconciliation and reopening. Remove disposable staging resources only
   after approval and retention review.

Manual approval is mandatory before provisioning/config changes, any deployment,
Machine stop/restart, traffic/autostart changes, data upload, restore or cleanup on
Fly. Also require a human decision for incompatible schema, missing/partial backup,
unknown digest/mount/UID, inability to quiesce, insufficient disk, mismatched sample,
post-backup data loss/reconciliation, privacy exposure or missed recovery objective.
This worksheet does not authorize any of those actions.

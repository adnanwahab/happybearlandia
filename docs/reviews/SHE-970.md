## Decisions, limits and next action

This is an offline preparation slice, not live automatic Linear intake. Search
requires a human-exported, pagination-complete snapshot for all three requested
families. Completeness is an operator assertion; title-token matching can miss
semantic duplicates. Live authenticated backlog export and final editorial
review remain human prerequisites. Before opening any ticket, refresh the live
duplicate search, validate consent, review sanitized evidence and obtain separate
authorization for the external write. No publishing transport is provided, so
review cannot open a ticket automatically. Manual writes are not transactionally
deduplicated by this tool. Queues/decisions are local trusted files, not an
approval authentication system. Full private queue must never be attached to a
public issue; preserve it locally under the source's retention policy.

Current collector counts cannot establish individual consent receipts or support
individual withdrawal. Patch legacy row consent is unavailable. Neither becomes
publication consent. Do not enable live persistence/export until ownership of
derived expiry/withdrawal is established. The two input databases are separate
snapshots; the adapter does not assert a shared transaction or invent model/run
provenance. No model/ODD changes are necessary: no simulation mechanism changed.

Preserved policy checked against `ops/patch-voting/queue.js`,
`.github/workflows/auto-merge.yml` and `.github/scripts/auto-merge.cjs`: curated
closed ballot defaults to 5 upvotes/+3 net and verified dependencies; drafts,
protected branch/check requirements, exact-head independent human approval,
holds and separately opt-in guarded auto-merge remain intact. No one-vote quorum
was enabled. Runtime repository variables were not changed or independently
inspected. No source data, production configuration, shared roadmap, deployment,
merge, ticket, PR or external message was written.

## Delivered slice and decisions

- `world/wander/route.js`: pure seed-stable bounded street route and controller.
  Procedural grid only: 64 candidate cells, four unique nearby synthetic building
  IDs, 344m closed loop, segment/footprint exclusion and loaded-road validation.
- `world/wander/panel.js`, `world/index.html`: native disclosure/buttons, polite
  stop prompts, explicit cosmetic/synthetic labels, End/Escape and manual-input
  cancellation, cleanup, keyboard focus and 44px button minimum height.
- `world/render.js`, `world/canvas2d-world.js`: normal renderer adapters reuse
  their existing frame loops. Three.js gets aerial movement; Canvas2D and reduced
  motion get static manual stops. No model-control API reaches Wander.
- `world/wander/README.md`: assumptions, support boundary and adapter contract.
  `test/wander.test.js` and `test/e2e/wander.e2e.js`: route, panel integration,
  model isolation and normal-entry browser coverage.

Source-map roads do not establish pedestrian safety. Sourced/saved maps show
unavailable until a verified access contract exists. Any blocked/flooded building
also disables the route conservatively. This is an aerial stroll, not physical
resident travel. Prompts name synthetic kind and actual generated building ID;
no fabricated landmark names or factual scene stories. New sessions repeat the
same sequence from town seedKey and presentation-only round counter. No model
RNG is consumed. Runtime has no new fetch, storage or telemetry.

ODD review compared `docs/models/legacy.md` with `world/gen.js`, `world/sim.js`,
`world/legacy-checkpoint.js` and both renderer adapters. Wander changes no model
mechanism, scheduling, inputs, IDs, clocks or mappings, so no ODD rule update is
needed. The model's existing clock may progress while viewing; paused-checkpoint
comparison and seed-matched continuation separately verify presentation isolation.

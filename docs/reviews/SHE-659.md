## Delivered behavior and decisions

- `world/render/inspection-freeze.js` owns a page-local gate with capture failure,
  unsupported state, idempotent clear, frame interval counters and removable UI.
- `world/render.js` continues normal playback/fixed-minute stepping before the
  frozen branch. It holds camera and existing matrices, skips visual updates and
  renderer adaptation, and renders on the existing frame loop. It disables camera
  controls during capture and restores their prior enabled state on release.
- `world/render/magnetic-picking.js` uses one ray for a zero-radius query; frozen
  World requests that mode. Existing source IDs/instance indices are reused.
- UI distinguishes scene freeze from model pause. Route events clear freeze;
  switching to Population/Business/tile view clears the gate on the next frame.
  Population/Business/tile captures are unsupported. Canvas2D has no new control.
- Frame count/max interval are presentation diagnostics only. No timers, new
  animation loops, model RNG, data sources, locations, actions or causal effects
  are introduced. Model rules/ODD descriptions are unchanged.

Frozen inspection uses current model facts. It does not assert capture-time facts
or produce a replay checkpoint. Model ticks are not held by this presentation
control. Exact geometry raycasting is narrower than magnetic selection but does
not prove pixel-accurate raster selection for discarded/transparent fragments.
Asynchronously replaced geometry and live building edits during capture remain
risks; full framebuffer/ID-buffer capture would be a separate hardening slice.

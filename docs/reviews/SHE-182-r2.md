## Delivered publication slice

`.github/scripts/sync-merged-pr.cjs` maps both `mini/SHE-182` and
`mini/SHE-182-r2` (and other positive numeric issue/revision identifiers) to the
original issue. Branch identity is authoritative; titles/bodies cannot redirect
the write. It requires an actually merged closed PR, matching event repository,
and matching head and base repositories. Forks, missing identities and malformed
branches produce no network requests. The canonical GitHub PR URL is constructed
from the checked repository and PR number.

`.github/workflows/linear-merged-pr.yml` runs offline tests and then executes
trusted base source on `pull_request_target: closed`, with read-only GitHub
permissions, no persisted Git credentials and a two-minute job limit. It never
checks out the worker head in the privileged job. Its Linear key is supplied only
to the sync step. The helper resolves the exact Linear issue and upserts a merged
PR evidence attachment. It does not change issue status, approvals, comments,
merge anything, deploy, or access production data. A merged report alone must
not mark acceptance Done.

The attachment API's [issue-and-URL idempotency](https://linear.app/developers/attachments)
makes rerunning a failed/uncertain job safe. Calls have 30-second timeouts;
HTTP/GraphQL/identity/transport failures stop the job with sanitized reasons.
No automatic retry loop is introduced. Rerun the failed Actions job after fixing
the reported operational hold; the Actions summary records skipped/linked state.

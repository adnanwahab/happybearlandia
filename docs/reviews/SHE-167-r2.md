## Delivered behavior

`world/render.js` now passes `autoActivate:false` to the existing Population
host. Ordinary World exploration therefore does not start its dense model.
The existing toolbar starts the same configured 10,000 residents on demand.
`world/population/world-view.js` retains explicit `living=1` activation and
`world/render.js` retains saved Living checkpoint restoration. No generator,
model version, seed, rules, weights, simulation clock or checkpoint format changed.
The legacy exploration model remains distinct; it is not a lazy Population cohort.

The updated benchmark uses ordinary `/world?people=20&seed=42&renderer=webgl&quality=LOW`,
without demo or living opt-out flags. It retains machine, seed, model config,
provenance and optional heap/device-memory observations, and now records the
host's startup-frame diagnostics. These are render-call observations, not proof
of display presentation. Missing heap readings remain null. No automatic
population reduction based on approximate `deviceMemory` was introduced.

## Remaining acceptance

WebKit cannot stand in for shipping Safari. Actual browser activation/failure cases
remain unexecuted. No million-row backend exists (explicit Population cap: 100,000),
and no selected paged/cohort architecture or measured allocation budget is supplied.
This slice removes automatic dense allocation from ordinary entry, but does not
satisfy the full million-resident architecture or performance acceptance.
Next: verify browser cases and capture target-device measurements on a host that
can serve and launch browsers, then select/integrate a million-resident backend
using those budgets. No merge, deploy, production load or public performance claim.

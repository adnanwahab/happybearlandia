## Next integrated slice and prerequisites

First obtain two source-backed observed network fixtures, or an explicit product
decision that a separately labeled synthetic demonstration is the intended scope.
The latter still would not satisfy the current observed-fixture acceptance.
No external outreach or data acquisition was performed.

Before UI work, establish a versioned producer contract containing source and
dataset revision, network/system and entity IDs, observation timestamp/timezone,
capacity/load quantities and compatible units, bounded spatial support and its
coordinate reference/projection, evidence/input references and missing-data flags.
Document whether observations are point, link or service-area records. Point or
district samples alone do not justify interpolating a continuous contour.
Map the selected data into World coordinates and time explicitly; do not equate
City month IDs with Population ticks or calendar dates. Any interpolation rule
needs a declared support mask, assumptions and verification.

Then implement one bounded system through normal `/world` controls: validated
source → fixed unit legend → bounded section → keyboard-selectable hotspot →
exact source inputs. Hide unsupported systems. Keep missing coverage distinct
from zero load; failed validation/loading must clear stale overlays and provide
an actionable status. Reuse recorded values rather than rerunning a model while
scrubbing. Keep the adapter/contract owned by one implementation task before
splitting renderer and inspector work.

Acceptance checks for that slice:

- Compare both observed fixtures' exact values, dates, IDs and source-input links
  through unit, integration and normal-entry browser tests.
- Exercise absent system, missing geometry/date/units, invalid or nonfinite
  quantities, zero capacity, loading failure, retry and replacement cleanup.
- Verify mobile control reachability, visible keyboard focus, hotspot keyboard
  activation, and a static reduced-motion alternative with the same values.
- Reuse the existing renderer frame loop; instrument overlay work and frame
  intervals, record before/after pacing on the same host, and dispose geometry,
  materials, listeners and pending work on replacement/hide/pagehide. Verify no
  callbacks survive cleanup. Existing profiler code is not overlay timing evidence.

Material risks: unsupported spatial interpolation, stale source/date pairing,
unit mismatch, whole-city values implying local hotspots, and unbounded GPU work.
External prerequisite is a trustworthy dataset with permission/provenance and the
spatial/time mapping. Device performance remains a separate measured check.

Cross-document navigation discards the outgoing audio owner. Starting a new
context in the incoming document from saved volume would neither guarantee
continuous blending nor honor the current fresh-off ambient contract. A fade
before location assignment would leave a load gap and no arrival ambience.
Neither shortcut satisfies the requested player moment. Native visual page
transitions do not retain the outgoing JavaScript audio context.

The shared schema has reduced **motion** and volume, not a separate reduced-audio
setting. Preserve volume zero as mute, existing independent ambient off, and live
motion preferences. If a reduced-audio control is introduced, define its semantics
explicitly rather than pretending the existing motion checkbox is that setting.
Current tests establish bounded source allocation within a mixer, not absence of
duplicate contexts after repeated cross-view navigation or BFCache restoration.

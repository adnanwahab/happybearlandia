## Audit and coordination

Read repository AGENTS.md, readme.md, docs/design.md, implementation-plan.md
(especially SHE-196), patch-voting README, improvement feedback contract. No
root docs/architecture.md exists. Inspected server.js routing, ballot HTML/JS,
API/store, queue, impact/GitHub contracts and their existing tests, merger script
and workflow. GitHub read-only PR search found #547 (player patch loop) and #546
(redacted logs); checked their descriptions against current checkout. This is
not a claim of a complete PR review or live GitHub check-state acceptance.

Existing defenses: exact Origin, JSON-only writes, explicit literal consent,
allowlisted fields/context, signed HttpOnly SameSite=Strict path-scoped cookie,
parameterized SQL, private pending suggestions, validated repository-specific PR
URLs, textContent DOM rendering and constrained local World return navigation.
No user-text auto-linking or public suggestions endpoint. Aliases are same-origin
307s; validation remains at the canonical destination. No auth/alias changes.
Raw hostile text is deliberately retained for private human review, not stripped
or interpreted as HTML. Later consumers must escape it for their output context.

Identified/fixed: request.text buffered an unbounded body before checking its
size; streamed byte accounting now cancels at >2048 bytes. Per-token throttles
could be bypassed by clearing cookies; durable shared action budgets now bound
accepted mutations across tokens (120 changed votes/minute, 30 suggestions/hour).
Same SQLite transaction rolls back throttle counters and writes on rejection.
These conservative limits are policy assumptions, not measured traffic capacity.
No schema migration, source/model changes, new personal data or telemetry.

Reviewed copy retains optional participation, unchecked/nonpersistent consent,
no name/email request, browser-token limitation, opt-out stopping future writes
and prior feedback remaining private. Seed alone is not reproduction evidence.
Synthetic model labels, matched-run evidence and unavailable-impact copy remain.

Configured policy preserved: closed curated ballot, >=5 upvotes and >=+3 net,
verified dependencies; worker creates draft PRs. Merger remains owner opt-in,
requires exact-head CI and independent human approval, no holds/unresolved
threads, branch protections and applicable required checks. One-vote quorum is
not enabled. Merging and deployment remain separate. No live settings inspected
or changed; local configuration is not evidence of production activation.

## Limits, rollback and next action

Shared budgets can be consumed by an attacker, denying legitimate writes until
expiry; they bound stored mutations rather than prevent network/invalid-request
CPU floods. Slow bodies still require ingress timeouts/concurrency protection.
Cookie resets can still manufacture separate voters within the global budget;
this is not authenticated uniqueness or election-grade Sybil protection. Existing
per-token/secret-loss behavior and privacy boundaries remain unchanged. Distributed
hosting requires coordinated storage and operator-reviewed ingress protection.
No live load test, outreach, service activation, merge, deployment, external message
or production-data change occurred.

Rollback: revert this issue's API changes to restore prior read/limit behavior;
no data rewrite or migration is needed. Retain existing private DB and signing
secret; do not reset votes. A rollout owner should weigh reverting flood limits
against the restored cookie-reset risk. Next: run dispatcher integration and
focused browser smoke in a listen-capable staging environment; review shared
budget suitability against expected traffic before separately authorized release.

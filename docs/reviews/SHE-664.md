* `world/city-council.js` is reached through `world/challenges.js` and
  `world/challenges.html`. It reviews authored mission policies and tracks trust
  for the three illustrative households in `world/follow-family.js`. These records
  have no building identities, coordinates or recorded civic-request receipts.
  Turning testimony or a pending proposal into a resident request would invent
  an action and spatial association.
* `world/living-city/emergent-quests.js` supplies a better request contract:
  entity collection/ID, source observation, measured value/unit, month/revision,
  seed, model/rules versions and provenance. Its text is an authored interpretation
  of modeled needs, not evidence that a resident submitted a request.
* `world/living-city/quests.js` initializes the current playable request page with
  `createCity`, an explicitly synthetic fixture. Workers can resolve through
  household → unit → building. Those fixture buildings have no geographic
  geometry. Business, facility and utility requests have district identities;
  district membership does not establish a particular originating building.
* `world/living-city/page.js` shows request evidence and a home description, with
  a separate event inspector. It has no geographic scene projection or paper-plane
  docking interface. `world/render.js` operates other model authorities; joining
  local IDs from this City scenario to its residents or buildings is unsupported.
* A real reuse path exists: `world/city/seed.js:createCityFromArea` retains OSM
  geometry and source IDs, and `world/city/lab.js` exposes area import. Its units,
  population and assignments remain synthetic assumptions. This must not be
  described as real residents making requests. The importer alone does not wire
  recorded quests, a selected checkpoint, scene projection and inspector together.

The discrepancy is an integration prerequisite, not a lack of any geography
support. No fake coordinates, cross-model identity joins or causal effects were
introduced to bridge it. Existing ODD descriptions remain accurate because no
model inputs, rules, scheduling or retention changed.

## Next independently verifiable slice

1. Use one selected monthly City checkpoint with area-derived buildings and
   evidence-backed quest records. Preserve its source dataset, seed, versions,
   revision, arm and month. Choose a host that can inspect that same checkpoint;
   do not silently replace the challenge sandbox or World Population authority.
2. Resolve only housed household/worker requests through recorded unit/building
   references. Require valid source geometry and an exact matching source entity.
   Skip missing/nonfinite measurements, unsupported entity types and missing
   origins. Define whether the marker represents discovery-time or selected-time
   need and retain the corresponding source observation. Completed requests must
   not masquerade as fresh needs.
3. Add a bounded overlay and an inspector showing the exact quest and originating
   entity. Keep narrative interpretation and synthetic assignments visible beside
   OSM attribution. Validate origin projection and docking bounds; suppress flight
   when there is no clear mobile path. Use ordinary keyboard buttons, visible
   focus and a stationary reduced-motion alternative.
4. Measure actual frame intervals and overlay work locally, with bounded counters;
   cap concurrent markers. Cancel animations/listeners on checkpoint changes,
   replacement, page hide and disposal. Stale callbacks must not open another
   request or mutate a later selection. Do not enable live analytics.

Acceptance tests still required: successful request/entity opening; unsupported
type and missing entity/unit/building/geometry; malformed evidence; scene or
inspector failure; stale checkpoint/arm selection; mobile control exclusion;
keyboard focus; reduced motion; bounded work and complete animation cleanup.
Use deterministic local geometry fixtures explicitly labeled as fixtures and a
normal-entry browser journey. Sourced geometry is needed for real-place acceptance;
fixture coordinates cannot establish that acceptance.

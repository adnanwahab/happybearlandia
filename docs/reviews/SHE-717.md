## Decision and prerequisite evidence

Do not add a second family-state authority or script successful generational
outcomes. Source has substantial model support, so this is **not** a claim that
birth or aging is absent. The prerequisite is only partially verified:

- `world/house/family-system.js` registers canonical planning, consent, cancellation,
  delivery, care and aging. `world/population/population-growth.js` appends actual
  residents and lineage; parent columns remain ancestry authority. Financial
  household IDs are not a separate persistent family identity.
- `world/house/family-heritage.js` records seeded learning influences, not earned
  skills or predictions of actual families. `world/house/family-contract.md`
  explicitly limits append count, household size and fast-forward workload;
  grown children cannot create new financial households. Mortality is absent.
- `world/population/checkpoint.js` and `model.js` preserve full state and aliases;
  family tests exercise restored continuation and absent-lineage older saves.
  These do not establish a challenge-receipt migration contract or independent
  recorded-checkpoint equivalence for a multi-year challenge.
- `docs/models/population.md` has the seven ODD headings but does not describe
  the implemented birth/adoption, anniversary aging, append-only lineage or
  inherited learning rules, nor link the family contract. Compare these exact
  paths before approving a model-backed challenge. Existing ODD inventory correctly
  identifies Population as authority; it does not fill this mechanism gap.
- Existing tests fail before any edits (details below). The long-history test
  cannot currently demonstrate its stated retention invariant. No inference of
  successful two-generation gameplay is justified by short continuation checks.

Read AGENTS.md, README, relevant design and implementation-plan sections (Playable
Life and emerging civilization), ODD inventory/Population description and the
family contract alongside source/tests. `docs/architecture.md` is absent.
The design requires immutable parents, matched seeds and explicit missing evidence.
The issue permits analysis-only results and explicitly gates this game on model
support; this review preserves that gate while identifying existing working parts.

## Next integrated slice and acceptance gates

1. Reconcile the ODD description and family subsystem contract against executable
   schedule, exact anniversary units, caps, identity, seed draws and inheritance.
   Diagnose the baseline history/keepsake failures without weakening assertions;
   install existing dependencies for the missing Three.js check. Re-run the
   focused suites. No external/editorial/hardware permission is needed for these
   local prerequisites.
2. Pin an authored Population fixture and complete checkpoint with source/model/
   rules versions, seed, time partition, adult and child IDs, and explicit toy
   assumptions. Prefer one actual parent-to-child succession; do not imply a
   grandchild or empirical forecast. Define whether the objective ends at adult
   age or an earlier named milestone before scoring. Do not set years directly
   to manufacture progress; use real supported steps and the workload cap.
3. Add a versioned challenge overlay to the existing House session/Family panel,
   with one bounded goal grounded in recorded care/practice and lineage. Keep
   starting checkpoints immutable and persist selected family identity separately
   from financial membership. Reuse canonical plan/cancel and runtime APIs.
   Own new challenge module, fixture, test and contract; isolate minimal House UI
   integration. No new births/aging mechanism is needed for this overlay.
4. Test actual success and failure from that same pinned source and seed; prove
   checkpoint nonmutation, unchanged original IDs and parent links, deterministic
   continuation, duplicate delivery refusal, supported schema migration, and
   atomic rejection of unknown versions. Verify replay against retained expected
   evidence before displaying equivalence; a seed match alone is insufficient.
5. Add normal `/world/house` navigation coverage with keyboard controls, cancel
   during execution, no source checkpoint, corrupt/missing lineage, and replay
   mismatch. Cancel retains only actually committed progress and awards no result;
   unavailable and mismatch states withhold scores. Label authored flavor,
   synthetic assumptions and computed results separately. No measured family
   observations are available in this proposed demo.

Unresolved: all challenge-specific acceptance, pinned demo, scoring, schema
migration, mismatch handling and navigation tests. This review does not deliver
those features. Model documentation and failing baseline evidence are the next
local work, not an external approval prerequisite or a claim of issue completion.

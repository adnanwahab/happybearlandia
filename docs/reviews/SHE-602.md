## Findings and scope decision

`docs/implementation-plan.md`, `world/invention/README.md`,
`world/render/README.md`, and `docs/reviews/SHE-567.md`.
`docs/architecture.md` is absent. Inspected invention landing, diorama
model/page/HTML/CSS, camera-presets module, World renderer integration and focused
unit/browser tests. No more specific AGENTS.md was found for these modules.

The primary invention route is a navigation page. Its Tabletop Block link opens
`world/invention/diorama/`, a DOM-only synthetic housing sandbox. The board's
`scale(.9)` and tabletop `scale(1)` are CSS presentation; neither is a World
camera. `page.js` clones committed proposals on entry and explicitly discards
unconfirmed edits on Exit/Escape. That existing behavior is documented and tested;
a camera return must be a separate action from explicit draft discard.

`diorama/model.js` owns two `block-home-*` synthetic proposal identities in a
200m square, housing model 1.2.0, seed 42, ten years/months 0–120. Confirm alone
runs the model. These identities and coordinates have no demonstrated mapping to
loaded World buildings, parcels, origin, run identity or clock. Arbitrarily
sending them into a geographic World would invent that mapping. The product
design requires demonstrated entity/time adapters across independent authorities.

`world/render.js` owns the actual Three camera, OrbitControls, streamed geography,
arrival/follow guidance and camera-preset mount. `world/camera-presets.js` already
provides bounded endpoint planning, return-pose validation, input interruption and
reduced-motion follow fallback. It is not mounted by the diorama, does not retain
its editor session, and does not validate an entire animated path. Existing camera
support therefore does not establish the issue's enabled case.

Do not relabel a CSS zoom as a validated World transition. Keep this issue at the
prerequisite-review stage under its proposal/backlog dispatch until the native
scene/edit-session adapter is specified and implemented. The owner's local
implementation authorization does not supply an identity mapping. No feature
acceptance or enabled behavior is claimed by this review.

## Next integrated implementation slice

One owner should own the native adapter interface before independent workers
edit consumers. No delegation is useful for this documentation-only audit.

1. Define a supported scene contract containing coordinate units/origin,
   stable proposal-to-scene identity mapping, geometry revision, validated camera
   pose/obstacles and a live edit-session reference. A detached synthetic fixture
   may prove mechanics but must remain labeled synthetic. Missing mapping,
   renderer or geometry must leave the camera and session untouched with an
   explicit unavailable explanation.
2. Keep the editor mounted while changing presentation mode. Separate Return to
   tabletop from Exit and discard. Snapshot camera/control state once; never
   transform parcel coordinates or model objects to animate scale. Resolve
   concurrent arrival/follow/preset/street/cutaway motion through one owner and
   dispose listeners on page exit.
3. Integrate validated endpoints and swept-path checks, bounded motion, manual
   interruption, and an instant reduced-motion cut. Revalidate geometry at return
   and during movement; unsupported return geometry must not force a collision.
4. Exercise the normal invention entry: edit a coordinate without confirming,
   enter/return twice, interrupt mid-flight, and verify identical draft identities,
   coordinates and unsaved values. Check keyboard focus/activation/Escape, touch
   input at a mobile viewport, reduced motion at start and changed mid-flight,
   and missing/unsupported adapter behavior. Assert run IDs, seed, clock, source
   and model results remain byte-equivalent. Capture route-specific screenshots
   or measured timing alongside browser assertions.

Material risks: independent coordinate authorities, editor loss on navigation,
competing frame-loop camera writers, geometry streaming during transitions, and
confusing a cosmetic scale effect with location-sensitive model evidence.
Prerequisite is local engineering of the explicit adapter, not production access,
live analytics, external outreach or a deployment. Browser/hardware evidence is
required after implementation; none is invented here.

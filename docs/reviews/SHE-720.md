## Plan, owned files and delivery

Bounded slice: explicit no-source landing → pinned authored request → frozen
supported housing template → matched City execution → success/failure receipt.
Prerequisites: existing challenge verifier, WebCrypto, current City version and
exact source-to-checkpoint/district mapping. Acceptance: preserve origin and
revision, declare terms before execution, refuse unsupported levers, preserve
immutable checkpoints/matched seeds, and never invent results after cancel,
missing source or mismatch. Risks: source authenticity is external, template
assumptions are normative, City/Population identities differ, browser unavailable.

Owned: world/quest-forge/*, test/quest-forge*.js,
test/e2e/quest-forge.e2e.js, this review/evidence; one native link added to
world/index.html. Shared roadmap not edited: this is an issue-worker record.

Delivered a strict civic-quest-request.v1 adapter retaining origin ID, revision,
source kind/reference/text, City model/district and full checkpoint hash. Only
housing-access has a compatible lever. Unsupported records receive explicit
refusals; empty records return no-source-data. Local hashes detect changes,
not genuine resident identity. Full schema/limits: module README.

A quest freezes a two-home / 1,000 synthetic USD action, 5,000 public capital
cap, 20 monthly steps and no-action control. The existing population,
employment and housing guards remain enabled. Success requires fewer unhoused
synthetic households citywide than the control. It does not promise a home for
the requester or a district-specific improvement. Entire source/terms/state
are checked before replay. Supplied outcomes, changed seed, state, guard,
revision or quest terms refuse. Origin and condition accompany the resulting
actual City observations, final states and complete monthly capital ledgers.

Normal entry: /world → Citizen Quest Forge → /world/quest-forge/ → Back to World.
Initial genuine-source view says no source data. Authored demo is explicit and
opt-in. Plan/source changes clear retired results; cancellation aborts and a
generation guard blocks late callbacks. This is a separate monthly City run,
with no implicit mapping to a selected Population resident/tick. No request
service, collection, live ingestion or publishing was enabled.

## External prerequisites and acceptance limits

No compatible genuine resident/civic request log was found in audited sources.
Civic routing/context and synthetic City quests are not such a log. A source
owner must supply permitted/redacted, revisioned records with reviewed exact
City checkpoint/district mapping and source authenticity. The adapter accepts
that normalized shape but does not authenticate it; logged-request tests use
only disposable fixtures. Genuine ingestion/real-origin acceptance is therefore
unfulfilled. Do not mark fully accepted from local tests alone.

Next: review the bounded adapter/template; connect a genuine source under its
access/privacy constraints; run rendered desktop/keyboard/mobile navigation,
cancel and mismatch journeys. No outreach, live load or production work needed
for reviewing this local increment.

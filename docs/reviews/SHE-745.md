The requested end-to-end block diary is missing. Existing useful pieces do not
establish a complete block event query and entity/time seek contract:

- `world/render.js` mounts `world/temporal/panel.js` at `/world`. The panel selects
  one historical OSM feature and loads object versions, or compares two bounded
  radius snapshots. It does not select a parcel group or query a block calendar.
- `world/temporal/api.js` exposes snapshot, diff and individual feature history.
  Snapshot queries are geographic bounding boxes, not a polygon event query.
  `model.js:snapshotDiff` produces mapping-added/removed/changed records with
  source-feature IDs and before/after evidence. Its `date` is the comparison's
  after-snapshot date, not the verified occurrence date of a physical change.
  A calendar must preserve the detection interval rather than assign that date
  to construction, a move, an opening or demolition.
- `model.js:normalizeHistory` preserves OSM object type, ID, version and edit
  timestamp. Versions can be redacted; way/relation histories lack historical
  node coordinates. `panel.js:history` explicitly states selecting a version
  does not reconstruct geometry or seek the live city. This is a viable source
  for a separately labeled mapping-edit diary, not proof of a block's physical
  life or a normal-entry entity/time seek implementation.
- `world/runtime/world-events.js` captures actual retained Population engine
  emissions, explicitly synthetic. `history-store.js` has bounded records,
  dropped-source/retention counts and nearest retained checkpoints. `eventsSince`
  filters sequence, not polygon or parcel membership. Sparse checkpoints cannot
  promise exact rewind to every event. A valid cursor with zero returned records
  is not by itself evidence of a quiet historical interval.
- `world/city/README.md` documents monthly City event/query/replay infrastructure,
  synthetic parcels and source geometry IDs for imported cities. Its identities
  and monthly clock remain separate from Population. Imported geometry does not
  establish an event-time World block mapping; the synthetic default has no
  invented geographic coordinates. Reuse needs an explicit adapter, not joins
  on coincident local IDs or a district-wide event presented as a parcel event.
- `world/spatial-events/model.js` is a research workload with ring tiles and an
  uncalibrated integer clock. It returns counters and hashes, not retained causal
  event records or a geographic/calendar mapping. It cannot supply this diary.

No probability, population count or causal explanation is inferred. Observed OSM
mapping evidence, synthetic initial conditions, computed engine effects and
decorative scene layers must remain separate. No new social mechanism is proposed
in this change, so existing ODD descriptions and inventory remain applicable.

## Next integrated slice and proposed contract

Prerequisite: choose one existing authority and implement its producer-owned
event/location/clock projection. A mapping-edit calendar can use OSM history;
a modeled-life calendar needs a verified City or Population spatial projection.
Neither requires new social rules. Do not silently combine those authorities.

Proposed `block-calendar.v1` contract (design only, no implemented API):

| Field | Required semantics |
| --- | --- |
| selection | Stable selection ID/revision, source/world revision, coordinate system and validated polygon or explicit authority-scoped parcel IDs. Declare intersection/containment and boundary/hole policy. |
| context | Authority, run/branch or source revision, model/rules versions, source identities, seed and inputs where synthetic. |
| range | Inclusive start/exclusive end in native clock units; explicit calendar origin/mapping or calendar unavailable. |
| records | Stable context-scoped event ID, supported type, exact entity ID, event-time location/membership evidence, native time, evidence classification and source record references. |
| date evidence | Exact sourced edit timestamp or bounded detection interval; retain unknown date rather than manufacture a day. |
| coverage | Complete/partial/unavailable, retained bounds, dropped/redacted/undated/unmapped counts and pagination cursor. |
| counts | Per-type/per-date counts derived from the identical filtered records; declare page counts versus full-query totals. Deduplicate by context plus event ID. |
| seek | Same authority/context/entity and exact supported checkpoint/time, or an explicit unsupported/missing checkpoint reason. Never switch run or clock implicitly. |

For moving entities, define membership at event time. Current residence/position
is insufficient. Requests and responses must bind selection revision and context;
cancel pending requests on selection/run change and reject late completions.
Bound query size, retained records and page rendering. Render source strings as
text and preserve mapper identity sanitization.

Missing-data behavior: complete coverage plus zero matches may say “Quiet period
in these records.” Partial/redacted/truncated coverage says “No matching retained
records; history incomplete.” Unknown membership/date stays unknown and is
accounted for outside dated cells. Network failures clear stale counts and expose
retry; unsupported seeks never move the camera/time to an approximate entity.

### Deterministic representative fixture specification

This is an acceptance fixture specification, not an executable fixture or observed
dataset. Pin one authority, versions, source/run ID, explicit selection revision,
clock mapping and initial inputs. If stochastic, pin seed 745 separately from
UI choice state. Include parcels A/B inside the selection, C outside, and explicit
boundary and hole cases. Supply two supported A events and one B event on two
dates, one C event excluded, one undated record, and a duplicate source event.
Expected dated total is three after deduplication, with per-day/type totals
matching the returned records. Unknown-date count is one, not an invented date.
Use a second context reusing a local event/entity ID to test isolation. Include
complete-empty, source-loss, redacted, unsupported-type, absent-checkpoint and
late-response variants. Preserve the raw source records alongside expectations.

Acceptance work, in dependency order:

1. Producer tests establish identity, event-time membership and clock/date
   semantics on the chosen authority. Document actual supported types.
2. Connect selected polygon/group through `/world` to bounded queries and the
   calendar; reconcile every displayed count with returned records.
3. Implement exact supported entity/time seek and explicit unsupported states.
4. Verify deterministic fixture replay, context isolation, boundary cases, quiet
   versus missing evidence, retries, cancellation and disposal.
5. Browser-check desktop/mobile keyboard selection and entry seek through normal
   `/world`; inspect screenshots. Measure frame time and resources across repeated
   open/filter/close on named consumer hardware, or retain an unavailable result.

Risks: cross-authority identity/clock confusion, incomplete history misrepresented
as silence, arbitrary snapshot date presented as occurrence, stale async counts,
and omitted events mistaken for verified population/causal evidence. These are
unresolved implementation prerequisites, not evidence that the feature is done.

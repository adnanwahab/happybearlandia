# PR #547 — Player-voted Patches → GitHub App pipeline

**Branch:** `feature/world-patches-entry-20261117`  
**Target:** `main`

## Implemented slice

1. Persistent **⚡ Patches** World shortcut and scenario-preserving ballot navigation. Embed mode hides it.
2. Reused advisory, opt-in SQLite ballot and moderator-only suggestions. Optional validated World IDs can accompany a private suggestion. No player prompt can enter a coding agent unchecked.
3. Public curated patch lifecycle via `GET /api/patches` and evidence-gated `GET /api/patches/:id/impact`. The ballot UI shows vote threshold, GitHub PR state, and recorded matched-seed comparisons only when materialized.
4. Trusted GitHub App adapter signs short-lived JWTs, obtains repository-limited installation tokens, creates a task Issue and draft PR from an exact, locally tested agent SHA, and is connected to `--github-app-prs` in the existing dispatcher.
5. HMAC-authenticated `POST /webhooks/github`, bounded request body, known repository/PR identities, last-observed PR and exact-head core-journeys workflow statuses; no acceptance of unsigned updates.
6. Private matched-run evidence importer checks SHA-256, seed, scenario, state and metric parity before displaying deltas. No synthetic impact numbers added.
7. Focused Bun tests for store/status, evidence, webhook signature, and mocked GitHub App; Playwright smoke for World-to-ballot roundtrip. The existing core-journeys fast gate invokes the new Bun tests via `test/patch-voting.test.js` without editing protected GitHub workflows.

## Constraints and security

- Voting is advisory: maintainer-curated candidates only; closed ballot >=5 upvotes, +3 net, verified prerequisites. Existing exact-head review, CI and merge guard preserved; no branch rule changes.
- User-submitted patches are text suggestions, NOT arbitrary executable Git diffs. Only supervised agents on trusted worker hosts write code, with scoped file ownership, isolated worktrees and focused tests.
- GitHub App credentials are never in the browser and must reside on the worker host, not the public game server. Webhook HMAC secret resides on the server.
- A created PR is **draft**, and cannot automatically merge until the human review/ready action and repository protections are satisfied. The guarded merger is separately opt-in. Merged != deployed.
- UI handles missing impact evidence explicitly; existing curated tasks are often UI/performance changes, so a city simulation impact might not be applicable.
- Worker and web server must use the SAME private vote store or a replicated transactional equivalent for PR links and impact evidence; localhost defaults do not provide that.
- No production deployment, GitHub App installation, private credential provisioning or remote auto-merge toggle is performed by this code PR.

## Verification

- New source and tests were syntax-inspected using an isolated JS parser; that is NOT equivalent to Bun execution.
- Bun is not available in this tool's container, and the localhost World URL is not accessible from the GitHub connector. Full Bun and Playwright test execution is therefore pending.

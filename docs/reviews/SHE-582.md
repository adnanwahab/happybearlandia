## Next integrated slice

The missing privacy infrastructure is implementation work, not a requirement to
enable an external provider. A local disposable implementation can use a new
server-issued opaque session capability and an isolated in-memory expiring store.
Do not claim the present audit implements that slice. Account-backed identity,
durable multi-server storage and staffed moderation are external prerequisites
for a later public service, not prerequisites for disposable-fixture testing.

1. Define a versioned reaction target scoped by experiment, scenario/arm,
   run index/run ID, model version, event ID and exact simulation month. Resolve
   it server-side against that experiment's available event records. Reject
   ambiguous IDs, wrong months/arms/models, absent runs and unavailable evidence.
   Do not accept an arbitrary client receipt as verification. If resolution uses
   recomputation, disclose it and pin the manifest/version; never rewrite runs.
2. Issue a server-generated ephemeral ownership capability in an HttpOnly,
   SameSite cookie, with origin protection for writes and Secure on HTTPS.
   Bind every mutation to that principal. Private is the default on every create;
   sharing requires an explicit audience contract. A reaction ID grants no rights.
   Session expiry ends mutation rights; no identity recovery by display name.
3. Keep reactions in a separate bounded store with server-clock TTL, cleanup,
   total-capacity limits, request-size bounds, finite emoji allowlist, per-session
   and overall rate bounds. Proposed fixture values: 30-minute TTL and five
   writes per minute per session. These are synthetic product choices, not measured
   safety thresholds. Lost ownership must not silently create public content.
4. Add viewer-local hide and server-side report suppression. A report must not
   publish reporter identity or imply human moderation occurred. Reject free-text
   payloads initially. Allow owner deletion; block edits/deletes by other sessions.
   Exclude hidden/reported/expired content from visible results. Derive any count
   solely from authorized live records, or omit counters entirely.
5. Integrate native labeled emoji buttons into exact event receipts on
   `/world/future-machine.html`. Show private/expiry status and explicit unavailable,
   network, rate-limit and expiry states. Use textContent, keyboard focus and a
   polite status region. No animation is required; the same DOM controls must
   work with Canvas and reduced motion. No simulated crowd or popularity signal.

Acceptance checks must exercise the mounted route with two independent cookie
jars: private default/read isolation; explicit opt-in; successful bounded reaction;
cross-owner update/delete rejection; wrong target and expired owner rejection;
hide/report; capacity/rate boundaries; malformed payload and unavailable server.
Assert complete run/manifest/seed/event digests unchanged before and after actions.
Browser checks must open the normal page, select a genuine receipt, use keyboard
controls and test narrow layout, reduced motion, Canvas and failed requests.
Capture before/after on that route with disposable data. Persist no personal data,
send no invitations, and enable no public feed as part of the local slice.

## Delivered behavior and boundaries

World controls → Compare two objects → Start pinning enables two scene selections.
A and B retain original source IDs; a third normal selection cannot replace them.
Clear A/B stops capture, focuses the capture button and retains the other ID.
An occupied pinboard moves outside the controls disclosure so minimizing controls
cannot discard/hide its summary IDs. Native source-ID entry supports keyboard and
touch, including buildings in Canvas2D, whose existing scene picker picks people.

Same-type legacy buildings match footprint m², illustrative scene height m and
supplied levels. Residents match age in years and synthetic needs in points/100.
Zero remains zero; missing/nonfinite values say Unavailable. Different types or
authorities explain why common fields cannot be shown. Population capture is
explicitly unavailable because legacy/Population IDs and metrics are not mapped.
No conversion, substitute estimate or new simulation authority is invented.

Pins are immutable page-local capture-time snapshots, not saved/live model
values. Both records disclose actual activity run ID, model version, run seed,
town seed and modeled minute independently. Different clocks remain visible;
the interface explicitly disclaims causal/matched-run interpretation. Spatial
lookup and the existing activity snapshot reader leave source state untouched.
The full checkpoint regression verifies equality before/after capture and after
20 subsequent seed-matched modeled minutes, including retained events.

No model mechanism, seed, clock, input, event or scheduling change: ODD model
inventory/descriptions require no revision. No animation or graphics dependency
was introduced; reduced motion needs no special animation bypass. Controls have

## Delivered contract and limits

`POST /api/prediction-pool` supports create/join/read/commit/reveal/delete.
Default disabled. Local testing requires `HBL_LOCAL_PREDICTION_POOL=1` plus
loopback transport IP; remote callers denied even with flag. Cross-origin
browser writes denied. No live service enabled. 20 pools, 12 members/pool,
one-hour TTL, small requests. No list endpoint, shared analytics, messages or
public publishing. Responses no-store. Invites use fragments, removed after
joining. UI makes manual opt-in copying explicit; no invitations sent.

Host and member tokens are separate. Server keeps commitments; reads return
counts, no values, even to host. Lock precedes synchronous paired computation.
Failure locks the pool unavailable. Guesses cannot be changed after commit.
Numeric error and direction correctness are different measures; unchanged is
its own direction. No leaderboard or aggregate performance ranking is produced,
including with zero participants or missing observations. Revealed rows are
anonymous. Deleting participation removes its commitment and revealed row;
host deletion removes the whole pool. Expiry also removes access. Secrets live
only in page memory; reload loses host/member access. Retain the open tab to
finish/delete; restart clears all data. No durable identity/recovery is claimed.

Plan modelVersion, seed, policies, horizon, scenarioVersion, target month and
synthetic source are returned with the computed outcome. Exact plan/control
validation and metric units use existing prediction scorer. This is one modeled
pair, not empirical predictive skill. No City rules or new social ABM changed;
ODD inventory unchanged. The scenario is reproducible and participants can run
it independently; sealing protects peers' guesses, not secrecy of public model
code or mathematical outcomes. Local operator memory access is trusted.

Normal entry `/world/challenges.html` offers seed, horizon, selected policy and
metric, commit, refresh, reveal and deletion. Existing challenge input event
binding was scoped to #detail to avoid capturing the new panel inputs. Native
labeled controls work without animation; no new motion. Mobile/keyboard visual
verification remains outstanding.

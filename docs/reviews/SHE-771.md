## Plan, owned files and acceptance

Smallest complete local slice: one authored household budget checkpoint, two
private role capabilities, supported policy/strategy choices, a sealed server
receipt, two-party role switch, denial/missing states and deletion. Prerequisites:
Bun server; a single process; manual private delivery of the second key. No
provider, real household data, new service or production setting is needed.

Owned files: `world/mayor-resident/{model,api,page}.js`, `index.html`, README;
server import/API/static entry; challenges link; model inventory/description;
focused Bun/Playwright tests/config; this issue record and evidence. Shared
roadmap is unchanged under the issue-worker ownership instruction.

Material decision: use a separately versioned authored exercise rather than
invent City/Population identity or unsupported household strategy mutations.
Mayor supports unchanged/voucher policy; Resident supports usual/conserve
spending. All coefficients and the one seeded expense draw are pinned. The
control uses the same Resident strategy, so the policy delta has a declared
comparison. No claim of empirical validity or welfare effect accompanies it.

Role access is capability-based, not verified identity: the creator sees both
keys and must distribute them privately. Each subsequent request requires one
key; neither role can submit outcomes, change inputs, choose for the other role,
or overwrite a sealed result. Stale revisions reject. Switching requires both
players' requests and preserves the checkpoint/receipt. Either can delete;
expiry is one hour or process restart. No public catalog, links with secrets,
automatic messages, browser persistence, analytics or public publication.

## Smallest integrated implementation slice

Proposed owned paths: a new `world/scene-discussions/` contract/store/API/UI,
targeted `server.js` composition and `world/render.js`/persistence-panel wiring,
and focused unit/API/browser tests. Leave Future Machine personal bookmarks and
existing save contracts with their current owners. Keep shared roadmap files
unchanged in this issue worktree.

1. Establish explicit local capability rights for a newly created private thread:
   separate owner and reader/commenter credentials, hashed at rest, absent from
   public listings/logs, with revocation. Resolve and authorize the source before
   returning any source payload. Do not treat sourceAuthentication as viewer
   identity or retrofit ownership onto anonymous existing records.
2. Capture a new immutable source snapshot through normal World save entry.
   Pin save/checkpoint digest, authority, model/rules/runtime versions, original
   seed/configuration/geometry provenance, clock unit/origin/tick, optional stable
   entity and retained event identity. Validate event/entity existence against
   that source. Missing/evicted event history remains unavailable. Preserve source
   records and fork ancestry; comments never mutate simulation authority.
3. Mount the private thread from saved-experiment controls. Discussion opt-in
   starts unchecked. Add bounded plain-text comments/replies, immutable revision
   records, author edit/delete, owner lock/remove controls and explicit history.
   Render all untrusted text with textContent; support no active HTML. Deletion
   must erase deleted text from revisions as well as current bodies, leaving only
   minimal non-content tombstones needed to retain reply structure. Thread
   deletion revokes access and removes discussion content without deleting a
   simulation save referenced by other consumers.
4. Open an authorized shared thread by resolving its exact pinned source through
   the native World restore path. Deleted/expired/missing/version-incompatible
   source produces an explicit unavailable state, never the current live world.
   Define expiry for the new thread separately from non-expiring legacy saves.
   Do not infer rights over external source data from possession of a checkpoint.
5. Notifications remain disabled in the local slice. If a local unread queue is
   included, subscribe only on explicit opt-in; owner mute persists and prevents
   future queued notices. No email, invitations, outreach or live notification
   service is authorized by this issue.

Material risks: reader credentials must not leak through logs/referrers; reader
rights must not become write rights; source payloads must not bypass authorization
via an alternate endpoint; stale edits need revision conflict checks; deletion
must cover history; orphaned reply trees and expiry need transactional handling.
Separate wall-clock revision times from simulation time. Backups/retention and
production identity integration need an operator-reviewed policy before release.

## Delivered behavior

- Manifest, paged summary for the selected recorded month, then only the selected
  pair's detail. All 100 stable futures remain independently selectable; no
  unfiltered results download occurs in normal loading or replay.
- Three-entry / 1,500,000 serialized-byte LRU, preserving recorded seed zero.
  Abort plus generation checks prevent late responses replacing a newer selection.
  Inconsistent progress across pages is rejected and retried without mixing data.
- Recorded A/B states at months 0/12/24 drive metrics, retained events, entities,
  explanations and synchronized cameras. Pair/month/clause selection survives
  reload in the immutable preview URL. Missing checkpoints are never interpolated.
- Explicit queued/running/partial/completed/failed/unavailable and graphics states.
  No successful record is substituted for a failed selected pair. The no-WebGPU
  path retains timeline, distributions, metrics and keyboard evidence inspection.
- Metric outcome buttons and graph nodes reveal source clauses, mappings,
  assumptions, recorded events/entities, seed/month/model and limitations.
  Dashed assumptions differ from solid recorded references; missing causal chains
  remain unconnected and explicitly qualified.
- Entity table, focus styles, mobile text wrapping and reduced-motion behavior.
  The normal-entry browser run found an illegal receiver on native browser fetch;
  the coordinator fixed it and added a receiver regression. Mobile range diagnostics
  found overflowing distribution-note text; wrapping fixes the actual content.

## Performance method

Same synthetic fixture: seed 42, 100 pairs, 24 months, immutable preview
pp_ce00b29fc0f2a37d6288b1d7b1e1065a490a5465f65a452a4e8d05b7adc1a020.
Model: city-systems.1.1.0/constitution-runtime.1.0.0/policy-preview-mappings.1.0.0.
Pair seeds are the actual stored values; no forecasts or favorable effects added.

Baseline main8f2dbb88, precompleted local data, one warm-server sample per viewport:

| Metric | Desktop 1440×1000 | Mobile viewport 390×844 |
| --- | ---: | ---: |
| Initial API body bytes | 25,263,538 | 25,263,538 |
| API requests | 2 | 2 |
| First useful selected state + 100 points | 315.14 ms | 154.77 ms |
| JS heap snapshot | 32,944,312 bytes | 28,241,088 bytes |

The working viewer transfers 336,313 bytes: manifest 15,718 + two summary pages
33,525/33,538 + selected pair 253,532. That is 98.67% fewer bytes, with four small
requests replacing two large requests. A final clean-revision browser benchmark
will record readiness and heap snapshots. These are requestfinished response-body
sizes and local timing, not WAN latency, transfer headers or guarantees. Readiness
means selected recorded state plus 100 D3 points, not shader compilation finished.
Heap is measured at that criterion, not peak process/GPU memory. Dynamic graphics
loading is deferred; no physical-mobile claim is made. Local baseline receipts:
/private/tmp/hbl-sprint2-baseline/receipt.json. Benchmark output defaults to
/private/tmp/SHE-1042-benchmark, configurable through HBL_IMPACT_BENCH_OUTPUT.

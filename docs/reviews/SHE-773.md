## Delivered contracts and limits

POST /api/city-experiments/:id/circle accepts scenarioId, runIndex and consent.
Only completed experiments with saved metrics qualify. The room copies the complete
manifest and metric rows, retaining SHA256 of serialized manifest, experiment/run
identity and effective seed. No simulation is executed by a claim or vote. Sources
are exact metric IDs within that room, with a link to the original run archive.
The pinned values survive independently of future external archive availability.
Model outputs remain synthetic; user interpretation remains labeled separately.
No model rule, identity mapping, scheduling or ODD description changed.

GET or POST /api/city-experiments/circles/:id uses Authorization: Bearer capability.
POST actions: join, read, claim, vote, remove, leave, close, delete-room. Join key
only allows consent-based enrollment. Enrollment returns a distinct participant
key. Host key can read, moderate, close and delete. Participant keys allow own
content removal and vote replacement/withdrawal. Leave deletes that participant's
claims and vote and invalidates the key. Closed rooms still permit removal and
withdrawal. Unrecognized/missing keys fail closed. No public directory or summary.

Limits: 100 rooms per process; 12 enrolled keys per room; 60 current claims;
1,000 characters per claim; 24-hour expiration (purged on next service access).
Rooms are memory-only and disappear at restart. Keys remain in page memory,
never URLs or browser persistence. Copy owner key privately before switching to
participant access; there is no account recovery. Reopening requires retained
room ID/key and Refresh. No invitations are sent. Free-text opinions/questions
are user classifications, not verified factual correctness. Assertions require
one of the pinned sources; this validates provenance, not entailment. Only saved
final metrics are supported as citations in this slice.

Async refresh is manual. A capability represents a consenting session, not a
verified person; tally explicitly says this. Invite recipients can enroll more
than once within the cap. This is never a binding/public ballot. Public hosting,
identity verification, durable retention, operational rate limiting and content
review are separate prerequisites, not acceptance claims. Host deletion removes
all room content; participant withdrawal removes their contributions. Source run
archives are not deleted or changed by room deletion. Previously copied content
cannot be recalled. Sharing is manual/private opt-in only.

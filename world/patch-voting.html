Vote on the next patch

Keep playing while the game improves. Vote for the changes you'd like to see next. Results guide the engineering backlog; every patch still passes review and tests.

Optional. Playing does not require feedback. A browser token prevents duplicate votes; no name or email is requested. Avoid personal information. Uncheck to stop future submissions; already sent feedback remains in triage. Nothing is implemented automatically.

From your idea to the next game update

  1. Propose an improvement
  2. Community vote
  3. Maintainer review
  4. Codex creates a patch
  5. GitHub PR + CI
  6. Guarded merge and separate deployment

Community votes prioritize curated proposals. An agent only receives a bounded maintainer-reviewed task after voting closes and dependencies are verified. Generated code starts in a draft pull request. GitHub reviews and checks still apply, and merging alone does not confirm deployment.

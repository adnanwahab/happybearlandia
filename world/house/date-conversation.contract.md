# Additive conversation mechanics

Factory `createDateConversationSystem()` in `date-conversation-system.js`, descriptor ID `date-conversation`; internal saved `home.systems.dateConversation`. Install **after dates**, before cinematic observers. State <=48KB, receipts48, proofs32, events32, retained couples4. All progression observes actual pair/assignments/visits/local positions/core action ledgers/acknowledged photos/validated game inputs and actual committed intervals. No independent clock, people registry, forced movement/end or direct romance/skill/cash scores.

Wrap commands with `{system:'date-conversation',dateId,commandId,...}` (stable bounded commandId). Every inspector option has `.command` containing its exact mechanic request; wrapper adds IDs. Commands:

- `open {openingId}` selects one of six authored present-tense threads. `engage {style:'follow'|'share'|'invite'}` explores a detail, opens explicit fact choices, or proposes a real shared activity. `pace {mode:'continue'|'linger'|'move',contextId?}` changes rhythm. Linger needs two actual shared minutes. Invited activity completes only from fresh real activity evidence.
- `awkward {contextId:'art-taste'|'too-fast'|'rivalry'}` starts an explicitly authored misunderstanding. Art/rivalry need relevant supplied art/game places. `recover {optionId:'curious'|'clarify'|'playful'}` records a contextual recovery once, not a romance bonus.
- `discover {places:[DatePlace]}` max12, actual validated supplied places within800m. Six observation template opportunities are grounded in available actual name/category/POI details. `observe {observationId}` stores **noticed** only. `ask {observationId,intent?:'ask'|'invite'}` confirms an actual simulated preference from canonical traits/learned experiences or returns a reviewed actual-place plan. It never invents gaze, piano/poster, childhood or relatives.
- `position {contextId:'quiet-corner'|'side-by-side'|'view-side'}` returns `requiresReview:true, proposedDateCommand` (ordinary dates `move`, `follow:true`). No location mutation occurs. `active.context` becomes arrived only after genuine normal movement of both actual people to the authored coordinates. Camera hints are metadata for the renderer. These are authored date-world contexts, not surveyed booths/real noise observations.
- `pack {itemIds:[two distinct item IDs]}` selects exactly2 free fictional prototype props; partner has1 deterministic prop. `use-item {itemId,useId}` starts a fresh real evidence requirement; sketchbook and umbrella need a real first step AND a fresh acknowledged photo. `useId:'put-away'` cancels a pending prop use with no result. Pocket-game needs an installed actual bounded minigame venue. Props do not invent physical inventory/assets/food.
- `promise {kind:'show-sketch'|'partner-next-stop'|'visit-place',targetPlaceId?}` keeps <=2 active explicit promises. `fulfill {promiseId}` requires fresh actual matching photo/destination/core conversation evidence. `renegotiate {promiseId,optionId:'later'|'at-home'|'not-ready'|'close-together'}` records specific explanation, with no auto deadline penalty. At-home returns a reviewable `proposedHouseAction` and requires a real paired household `conversation` completion plus both actual participants still at home when fulfilling; it does not transport/enqueue anything. Completed promises retain their source evidence.
- `bookmark {op:'resume'|'later'|'close'}` stores one interrupted authored thread. Normal movement also bookmarks it. Resume preserves exact opening/line and requires actual reached quiet or side-by-side context.
- `disclose {key,value}` explicitly confirms one bounded current player preference from `factOptions`. Changes retain previous value. Facts are player-confirmed, never invented biography, and affect later thread wording.
- `reveal {op:'choose',choiceId:'quiet'|'playful'|'curious'}` fixes player and separately determined actual preference/need-based partner choice. Public sealed inspector hides partner choice/explanation. `reveal {op:'reveal'}` reveals the already-fixed pair and response, with no score bonus.
- `opportunity {op:'open'}` compares two competing next focuses with consequences. `op:'mode',mode:'paused'|'live'` selects UI timing; paused inspector requests pause, live gives an informational20min window. No auto selection/penalty/expiration. `op:'choose',optionId` returns ordinary activity proposal; only actual completion records following through. Passed focus is retained as a future suggestion.
- `setup {setupId:'tiny-trick'|'ridiculous-title'|'napkin-symbol'}` requires actual rehearsal/creative action. `payoff {setupId}` requires a ready setup at the same real venue and then a second distinct real action. No click-only payoff.

Inspector: `{active:{dateId,personIds,available,reason,locations,openings,thread,awkward,awkwardContexts,recoveryOptions,observations,spatialContexts,context,pendingPosition,inventory,itemUse,promises,promiseOptions,bookmark,reveal,revealOptions,opportunity,opportunityOptions,setups,pacing,lastPartnerResponse},facts,factOptions,learned,noticed,history,events,capabilities,unsupported}`. Each nested option carries `.command`. Thread offers3 engagement styles; pendingShare supplies explicit fact options. `proposedDateCommand` and plan/capture/game requests require normal UI/core action execution; no implicit execution.

Events include `{id,type,dateId,personIds,minute,text,presentation:'ambient'|'interactive'|'cinematic',source,sourceEvidenceId?}`. Ambient comes from actual arrivals/needs/attended lingering; interactive from authored exchanges; cinematic from explicit meaningful disclosures, evidenced promises/invitation/payoffs. Real significant moments use existing canonical date memory hooks. Local event ID stored globally as `conversationEventId` so global journal identity remains canonical. Cinematic rendering stays in separate existing module.

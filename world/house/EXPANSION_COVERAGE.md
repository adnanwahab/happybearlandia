# Household expansion: coverage of the 100 proposals

Audit date: 2026-11-04. Source: the user's “100 features … family life, creature care, god powers, and … home or dungeon” proposal. This is an implementation inventory, not a claim that the full design has shipped or been playtested end to end.

The new house entry point is **Household world**. The seven components in this expansion are:

1. `household-work.js`: Work & possessions, portable props, condition-driven chores, bargaining and delegation.
2. `household-agendas.js`: Wishes & promises, room agreements, repeated habits, sleep/social preferences.
3. `creature-keeper.js`: Creature care, trust, a demonstrated cleaning lesson and guardian support.
4. `underhouse.js`: A bounded excavation grid, actual resident work, resources, utilities and encounters.
5. `household-scenarios.js`: Explicit scenario goals, room blueprints, retained incident history and challenge manifests.
6. `household-expansion-ui.js`, `keeper-scene.js`, `scene/keeper-house-visuals.js`: The shared controls and small Three.js presentations connecting those systems to the existing household.
7. `guardian-powers.js`: Earned guardian spells, explicit gesture-command alternatives, furnishing-anchored influence, awakened furniture and witnessed intervention stories.

**Playable foundation** means the concrete core loop is represented by connected commands, state and outcomes; it does not imply every example or depth described in the proposal exists. **Partial** means a narrower related system exists but a substantial part of the requested mechanic remains. **Not implemented** means there is no implementation of the proposed mechanic; an adjacent feature is not counted as completion. Files below are relative to `world/house/` unless prefixed otherwise.

## Deployment and verification boundaries

The table identifies code paths and connected foundations. A passing unit test does not by itself prove every visual/interaction path is comfortable or every legacy save has been exercised. The expansion has focused component tests, and the shared UI still needs the same browser and save/restore validation as other house features.

In particular, the persistent household is **not networked multiplayer**, blueprint sharing is a bounded JSON workflow, underhouse travel/raids are small modeled activities rather than action combat, and the seed manifest is **not** a complete standalone world bundle. Physical divine-hand manipulation, drawn gesture recognition, playable dreams and a visual scenario editor remain outstanding. Guardian spells and living furniture now have bounded playable foundations; shrine influence is limited to actual anchor rooms, and guardian “myths” are witnessed event stories rather than an autonomous folklore simulation.

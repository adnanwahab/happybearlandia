# Influence ledger

Install `createInfluenceSystem()` from `influence-ledger.js` through the existing household registry. ID: `influence`. No automatic registration or client recording. Inspector is pure and does not initialize tracking. `mountInfluencePanel(container,{embedded:true})` returns `update({influence})` and `destroy()`.

Lives influenced counts distinct actual synthetic population indices participating in **completed** direct/queued house actions or canonical `HOUSE_DATE_ACTIVITY_COMPLETED` events in this household. It is gameplay reach, not causal benefit, agreement or a calibrated social-impact estimate. Default is zero, never346.

Core `applyHouseholdAction` creates direct/queued actions without `origin`; the existing autonomy adapter stamps `origin:'autonomy'` after admission. Completion requires the exact active action object, its actual house sequence, full progress for every actual participant, elapsed duration and a time no earlier than tracking began. Other explicit origins are excluded. Automatic Story Director activities use autonomy and are excluded; no inferred player chain. Core date activity completion follows an explicitly admitted mutually agreed date and actual shared attendance. Date starts, arrivals, travel/minigame/quest events without equivalent canonical completion evidence are excluded.

State is bounded below40000 UTF-8 bytes: population-index base64 bitset (up to100000 actual people), at most64 compact logs, at most128 in-flight action receipts. Active-source-aware action floor supports concurrent completions out of sequence, plus exact global event cursor prevents recount after retained logs expire. Population extension preserves existing bits under the same model prefix. Different prefix, shrinking population, corrupt bit/count or malformed receipts fail validation. New worlds start a new zero baseline; no manual reset/count-edit command.

Tracking starts at first prepare or new action admission. Preexisting completed actions/events are not reconstructed; already-running actions admitted before tracking are excluded. Retained event gaps disclose unavailable **global** record counts, not guessed missing household influence. Lifetime distinct count survives log eviction/reload. Logs show at most8 actual captured names/IDs and explicit full participant counts; JSON byte pressure can retain fewer than64 logs. Original evicted narratives cannot be recovered from identity bits.

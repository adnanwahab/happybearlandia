# Story Director integration

Register `createStorySystem()` from `story-director.js` in the existing registry. It uses existing prepare, advance, recordInterval and completeAction hooks, canonical model.minute, physicalHouseMembers, home.progression.rewardPoints, social traits/ties and home.systems.social.secrets. No private clock, person registry, wages or cash account.

`mountStoryPanel(container,{onCommand,onGoOut,onObserve})` returns open/update/destroy. `update({story: inspectedHome.systems.story, home: inspectedHome, members, minute})`; direct inspected story is also accepted. Route onCommand to existing householdSystemCommand with householdId; inputs include system:'story'. Load story.css. Buttons remain mounted during interval updates; wants change on the actual model day boundary. Dream select options/controls preserve in-progress user choice across updates.

`mountStoryControls(container,{onAdvancedChange,onGoOut,onObserve})` from story-controls.js is optional. Toggle defaults to simple, emits boolean. Host adds/removes `.house-simple` and opts specific advanced sections into `[data-house-advanced]`; module deliberately never infers which existing controls to hide.

`personStoryPresentation(inspectedHome,personId)` returns null or {type,glyph,text,cause,minute,intensity,source}, read-only. It uses existing actual emotions, with recent actual argument/mess/cuddle/want causes when the base emotion is neutral. Caller draws thoughts/poses; story module never mutates transforms or fabricates a cause. For raw home, saved story.lastMinute is its observed model-clock boundary.

Commands: interesting selects ONE plausible currently available existing activity via context.actionAvailability/startAction, skipping active actions, queues and manual walks. It returns accepted:false with an honest reason when none is feasible. want {personId,wantId} requests the relevant existing activity; completion, not clicking, grants five canonical rewardPoints and five personal lifetime Life Points, once per generated daily want. Three wants per current member rotate daily from installed furniture-supported activities; no reward reroll. dream {personId,value} delegates to existing Social setAspiration and projects its real progress and once-only award. No duplicate long-dream award system.

predict returns at most three conditional branches within 180 minutes; no fabricated calibrated percentages or mutation. recap {day?} returns actual retained story events, truthful coverage limit and a recorded highlight. partyType {value} chooses the behavior preference of an already active actual party; theme candidates are still admitted through actual action constraints. Party recaps count actual admitted visitors and attended completed story actions, exposing the original actual elapsed party stats. It does not claim to simulate outdoor grilling, dancing or unsupported board games.

Object histories use installed object IDs. Explicit object IDs and unambiguous matching object type/room are required; unanchored conversations are not assigned to arbitrary couches. Purchases are dated only if an actual furniture completion event with that object ID was observed; initial furnishings say purchase unknown. Actual completed uses count meals, naps/rest, cuddles, arguments and conversations. Interrupted intent counts nothing.

Secrets from completed private arguments live in canonical Social state with sourceActionId, source text and actual participant knownBy. Later attended Gossip transfers a known fact to its actual listener once and retains eight provenance transfers. It does not invent private thoughts. Existing player-authored Social secrets can also be shared by actual Gossip. Knowledge itself is game fiction, not claims about real people.

Neat/messy friction requires a genuinely dirty room AND dirty object, an actual previous user (lazy trait or existing messy quirk), existing canonical pair tie, and 30 actual attended minutes by the neat resident. Repeated identical interval callbacks cannot double count. Actual tie tension +3 once per directed pair/model day, with explicit cause. Existing personalityChemistry and relationship/emotion outcomes remain the underlying authority.

Retention: 32 current member desire states; 96 timeline events with byte trimming; 64 current object histories with three recent moments; 64 directed friction entries; 64 actual-person completion highwaters with an eviction floor; four party recaps. Validation caps serialized story state at 100 KiB, preserving room for date photos/memories under the combined 512 KiB systems cap. Removed member desire rows and removed-object histories are pruned. Read-only inspect does not create state. Replay duplicate/older completions are rejected by per-actual-person highwater even after timeline trimming.

Party behavior extension: Make Today Interesting prioritizes theme candidates. Birthday/Housewarming prefers actual group joke/welcome conversation. Date Night requests friendly paired interests conversation; romance remains behind existing explicit mutual-consent controls. Dance Party requests supported music playback/listening. There is no board-game or dance action in the present catalog; Game Night explicitly reports that limitation rather than inventing play. Outdoor BBQ uses ordinary actual cooking/dining, with grilling disclosed unsupported.

Autonomous party encouragement runs at most every 30 authoritative model minutes, only with life.enabled and life.autonomy. It requests at most one actual feasible action through autonomousAvailability/applyAutonomousHouseAction, preserving every participant’s work/school/care/departure constraints, active tasks, queues and manual walks. Source actors are actual financial-household residents, never guest IDs. Guests can participate only after actual door admission and action availability checks. Existing party ledgers and stats remain authoritative; no invitations, visits or outcomes are invented.

Physical-household/city limitations: story encouragement operates at the actual party household. It does not teleport residents, merge financial households, create offsite interiors, route a new excursion, or invent seamless travel. Existing Go Out/city/date travel remains the authority.

Moved-out desire rows are historical metadata keyed to actual existing person IDs and can survive the immediate move-out checkpoint. Validation requires real actual IDs, and the next prepare prunes departed people from active desires. This keeps authoritative roommate move-out atomic without inventing members. Expanded validation: 21 tests pass across story-director, roommate-runtime, party-runtime and party suites (131 assertions).

The configured chance is a game knob rather than a calibrated real-world forecast.

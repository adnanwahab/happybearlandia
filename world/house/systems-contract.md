Shared 90-feature integration contract (Models)

Canonical API: runtime.householdSystemCommand({householdId,system,type,...payload}). Worker records one kind:'house-system' entry in the existing retained householdTimeline. Replay executes the same pure module rule against the original full model. Runtime and worker remain authoritative; modules do not create another resident, wallet, weather owner or clock.

STORAGE CORRECTION: use home.systems[systemId], matching Social and Economy. Earlier commentary mentioned systemState; home.systems is the agreed field. home.systems is raw authoritative state in model.houses.homes; house inspection returns projections from inspectHouseholdSystems. Persisted module state must be bounded plain data and at most 512 KiB per home's combined systems. No functions are serialized.

Registration: system-registry.js registerHouseholdSystem({id,command,inspect,validate,actions?,...hooks}). Core system-installers.js owns static imports/adapters and calls registration after module initialization, avoiding house/employment static-catalog cycles. Modules export their own named functions; they should NOT self-register at top level or import system-registry. Models wraps Social's existing named signatures, Economy's forthcoming equivalent, Spatial's named functions, Lifecycle, and Root Lab. Tell Models the exact file/exports when landed.

COMMAND DESIGN: model-mutating rule functions are supported, matching existing life/party modules. command(model,home,input,context) receives input stripped of householdId/system but retaining type and payload. The framework executes on a structured-cloned full model + raw home, validates, then commits atomically preserving the outer model object. Throwing leaves original model, cash, people and clock untouched. Command must not advance time. It returns an object with accepted/result/events and optional recommendedAction (recommendations are not silently executed). Context provides startAction(request), actionAvailability(request), inviteGuest(request), sendGuestHome(request), admitGuest(request), actual householdId and current minute, all bound to the draft model. Modules reserve resources only after complete preflight. Existing savings/objects/people arrays are the only authority.

TIMED ACTIONS: descriptor.actions is a static catalog of {label,durationMinutes,minAge,roomId,requires,mechanism,objectTypes?,needRates?,pose?,minParticipants?,maxParticipants?}. Do not import employment/house runtime into a static catalog; split catalogs if necessary. New types are discovered dynamically alongside HOUSE_ACTIONS. Descriptor.actionPlan(model,home,request,participants) is READ-ONLY and returns {available,reason?,cost?,data?}; added cost is charged by the existing house ledger once, and data is persisted under action.systemData[id]. admitAction(model,home,action,request) commits already validated ingredient/stock reservations. It must not throw after a successful identical preflight. Recipes use a new cookRecipe action; selected Economy can disable legacy cook to avoid free servings/double charges.

HOOKS (all use committed simulation time):
- prepare(model,home,{minute}) before actor advancement and after player queue processing.
- advance(model,home,{startMinute,endMinute}) once after each internal fixed subinterval; no private timers.
- recordInterval(model,home,action,index,startMinute,duration) once per actual attended action overlap. Actual participant ID is model.prefix+'-p'+index.
- completeAction(model,home,action,completedMinute) once after all attendance and before canonical action removal/completion ledger. Recipe outputs and actual mealLots belong here, not an elapsed wall-clock timer.
- needRates(model,home,actionOrNull,index,minute,activity,baseRates) returns a rates object, no instant need writes. This can disable synthetic free HOME meals when pantry simulation is enabled and apply actual food quality/running utilities.
- inspect(model,home) is read-only and is exposed as inspectedHome.systems[id].
- validate(model,home) validates optional module state for full checkpoint restore; absent state is backward-compatible.

Current module IDs/path agreement: social => social-systems.js; economy => household-economy.js; spatial => spatial-system.js; lifecycle => lifecycle-system.js; lab => Root's forthcoming module. Models owns only registry/installers/core adapters. Studio owns Economy and roommates.js; Intelligence owns Social/progression/relationships; Engine owns Spatial; Root owns Lab.

NPC ROOMMATES: published final source is model.roommates (not the earlier draft houseRoommates). Runtime acceptHouseRoommate/moveInHouseRoommate aliases +moveOutHouseRoommate are wired. Actual admitted adult guest + host consent, existing bed capacity, guardian rules; original financial household retained. Core roommate-roster.js is a read-only layer used by Life/queues/inspection to avoid circular imports. advance hooks run start/end; syncRoommateHomes runs after householdDecisions. No permanent financial-household merge is claimed.

CENTRAL MEMBERSHIP: world/population/household-members.js exports householdMembers(model,h) -> copied actual-index array, setHouseholdMembers(model,h,indices), validateHouseholdMembership(model). Optional model.householdMembership[h] overrides contiguous starts after an append-only birth. Existing IDs/indexes never reorder. Use this iterator in Life/Lab/Social/Economy/profiles/creator/roommate rules instead of start+size. Financial membership remains separate from roommate physicalHouseMembers. Models updates all population core loops and checkpoint/return bridge.

House relationship adapter contract (owner: Relationships)

New module: world/house/relationships.js. Models owns integration; this module does not alter runtime/UI/model files.

Exports:
- personalityFor(model, personId): read-only deterministic {personId, traits:[{id,label}], preferredTopic, source}.
- inspectHouseRelationships(model, personId, {limit=12}={}): {personId, personality, relationships:[{personId,name,label,friendship,romance,tension,familiarity,memories,romanceAvailable,romanceReason}], source}. Uses canonical model.social.ties, no second relationship graph.
- completeHouseConversation(model, action, completedMinute): called once after BOTH actual action.progress values reach durationMinutes and before completed action removal. action is the canonical house conversation record {id,type,participants:[index,index],progress,start,until,durationMinutes,topic}. Replaces the old populationSocial(...).interact('talk') completion call; DO NOT call both. Returns {status:'recorded'|'already-recorded',event,text,minute,friendshipDelta,romanceDelta,factors,memory}. No need, cash or clock changes. Effects update existing model.social.ties and bounded shared memories. Completion attendance, IDs, committed time checked; per-pair completion time high-water mark prevents replay duplicates even after memory eviction.
- romanceAvailability(model, aId,bId,{mutualConsent=false}={}): read-only adult/nonfamily/distinct-household and explicit mutual-consent check. Friendly conversations never create romance or infer consent.
- validateHouseRelationships(model): validates optional extension fields for checkpoint integration.

Canonical persistence: existing model.social.ties entries retain their existing fields, extended with lastHouseConversationMinute, lastHouseConversationId, and memories entries {actionId,minute,event,text,topic,durationMinutes,factors}. Deterministic personalities derive from config.seed + exact actual ID, requiring no second saved trait registry.

Optional romance completion contract: canonical action.relationshipIntent='romantic' plus action.consentingPersonIds=[exactAId,exactBId]. The integrator must obtain explicit consent and retain these fields on the action for replay. Without them all conversation effects are friendly only. Invalid age/family/consent requests throw atomically. Eligible mutually consenting pairs with friendship >=55 and tension <45 can gain bounded romance from an actual completed conversation; otherwise the result is romance-declined with no romance increase. This does not invent consent or make a dating commitment. UI can expose personalityFor and inspectHouseRelationships immediately; action admission remains Models' responsibility.

Expansion API: HOUSE_PERSONALITY_TRAITS now 10 declared gameplay traits (Neat/Lazy/Social/Introverted/Romantic/Creative/Ambitious/Funny/Hotheaded/Foodie), personalityFor returns 3–4 unique compatible seeded traits. HOUSE_CONVERSATION_CHOICES lists chat/joke/gossip/compliment/argue/apologize/flirt/interests/day. Optional canonical action.conversationChoice selects behavior; omitted defaults chat for older saves. Model admission MUST allowlist and retain this field. Flirt requires romantic intent + exact two consentingPersonIds. Per-pair canonical tie.directed[actualPersonId]={trust,attraction,resentment} stores distinct perspectives, shown in inspectHouseRelationships rows as directed plus other Sim personality. Actual completed conversations alter these bonds; arguments/apologies/jokes and traits affect outcomes, memories retain choice+factors. No UI or core model writes made for this expansion; Models integrates canonical action fields and Viz renders choices.

Creator profile integration: personalityFor honors model.houseProfiles (schemaVersion house-profiles.v1) people[exactPersonId].traits when 3–5 unique allowed trait IDs; .interests when 1–6 unique existing topic IDs. The first interest becomes preferredTopic and a copied interests array is exposed. Invalid/absent fields independently fall back to the existing seeded derivation, preserving old-save personality values and source exactly. Profile values are never mutated; root profiles.js owns canonical validation and creation. Expanded HOUSE_PERSONALITY_TRAITS export is already available.

Created household relationship compatibility: familyRelated treats explicit houseProfiles.households[exactHouseholdId].relationship='couple' or 'roommates' as permission to evaluate adult same-household romance eligibility, rather than assuming blood family. Actual parent, descendant and shared-ancestor checks still block romance. Explicit family, missing/invalid classification and legacy households retain conservative same-household exclusion. Consent and minimum adult ages remain required. No household classification is inferred or rewritten by this adapter.

Explicit dating milestones: canonical completed conversation action.relationshipDecision='askOnDate' requires romantic intent + mutual consent, friendship>=55,romance>=25,tension<45 and notalreadydating; emits outcome.event='first-date' and tie.dating=true, otherwise date-declined. action.relationshipDecision='breakUp' requires existing tie.dating and represents the player's explicit boundary decision; actual completed conversation emits breakup, tie.dating=false,romance=0. No spontaneous date or breakup is invented. Models must admit/retain optional relationshipDecision on canonical actions to expose these interactions; Rootlife consumes returned outcome.event/text/memory as actual milestones. Argument event already emitted for conversationChoice='argue'.

Relationship lifecycle gap fixed: completed conversationChoice='argue' on an existing dating bond ends dating ONLY when resulting canonical tension>=60 and at least one resulting directed resentment>=60. Actual tie.dating becomesfalse,romance0; same real completion returns event='breakup', memory.event='breakup',factors.relationshipChange={cause:'completed-argument',tension,resentment:{actualPersonId:value}}. This replaces the argument outcome for that completion; no extra fabricated feed row. Mild arguments remain arguments and do not break up. Apologies emit reconciliation, raise directedtrust5 and lower resentment10/tension12. Warm memory recognition includes reconciliation/first-date; prior tension includes argument/breakup. Return romanceDelta now reports the actual decrease when breakup clears romance.
First-date currently REQUIRES canonical action.relationshipDecision='askOnDate' + explicit mutual romantic consent. No autonomous friendly/flirting event is falsely labeled a date.

Observer, partner and other romantic participant must all be stationary (remaining0), share the exact existing currentLocation and district, with observer within40m of both. Absent/otherlocation/traveling/minor witnesses doNOTtrigger. Up to8 sorted existing ties react; only observer perspective trust-8/resentment+12 and couple tension+6, bounded0–100. Existing romance/needs/cash/clocks unchanged. One retained witnessed-jealousy memory with actual participant/location IDs is attached to the existing couple tie; result.witnessedEvents exposes the SAME observed memories for actual event presentation. Per-pair lastWitnessedJealousyMinute/ActionId high-water prevents replay duplicates after memory eviction. validateHouseRelationships checks optional witness-only extensions too.

# Good evening / imperfect dinner

Register createEveningSystem() from evening-system.js; descriptor/persisted id evening. Root owns registry and UI integration. No private clock, person, money, servings, relationship or physical furniture authority is created.

Commands use householdSystemCommand with householdId/system:'evening' and stable bounded commandId:
begin {approach:'quiet'|'cook'|'music'|'watch',personIds?}
choose {choiceId:'start'|'help-clean'|'repair'|'handle-fire'|'adapt-quiet'|'adapt-music'|'retry-dinner'}
exchange {kind:'joke'|'help'|'appreciation'|'tension'}
finish
recall {keepsakeId}
profile {personId,name?,favoriteActivity?,concern?,aspiration?}

Profile contract for Studio: type:'profile' targets a real physically present current household or resident roommate. Name is explicit user input 1–50 characters and writes canonical model.houseProfiles.people[id].name. It never changes the demographic ID/index or household assignment. If a legacy resident has no complete profile, the module copies their existing deterministic personality/interests and CURRENT house-renderer appearance defaults/palette to create a schema-valid profile without a rename changing appearance. Existing complete profile fields are preserved. Concern is explicit user-authored text at most 160 characters; favoriteActivity must be one of inspector.favoriteActivities (empty clears); aspiration must be one of inspector.aspirations canonical IDs (family,wealth,chef,musician,scholar,home). Favorite and aspiration update existing Social favorites.hobby/setAspiration authority, so aspiration awards remain canonical/once-only. For resident roommates, personal Social state remains at their original financial household. Inspector profiles[] resolves {personId,name,favoriteActivity,concern,aspiration,canEdit}, plus favoriteActivities[] and aspirations[] options. No favorite or worry is invented from default traits. A current need concern remains separate from user-authored concern.

Inspector root {schemaVersion,minute,situation,approaches,active,keepsakes,recall,profiles,favoriteActivities,aspirations,limitations}. situation includes actual at-home/away person IDs, actual homebound trip ETAs only, tired/lonely/hungry actual values, prepared servings and a readable summary. All-home is said only when true. Begin is optional and does not start or interrupt an action by itself.

Active stages preparing/serving/settling/connecting/reflecting/remembering/observing. choice start asks the existing activity dispatcher for one currently feasible real stage activity. Cook uses actual installed stove/cost/servings; prepared food shifts directly to sharing; music uses real stereo and capacity; quiet supports real nap/read. Existing player actions, queues/manual walks, work/school/care constraints and actual location must permit every participant. No action duration/time is advanced by a command. help-clean performs genuine kitchen cleaning; it is not a free cooking bonus. Existing stove mechanics support one active cook.

Exchange kinds are actual 15-minute friendly conversation actions with distinct existing styles: joke/hobbies, day/plans(help), compliment/day(appreciation), apologize/day(tension). Tension option requires an actual canonical tension tie. Outcome comes from the real completed action/canonical relationship memory after attendance; it is not fabricated at click time. Scene replies distinguish actual reconciliation, awkwardness, shared interests, reconnection and argument. No instant score bonus is awarded.

Active currentActions[] exposes actual admitted IDs, participants, requested/doing status and committed attendedMinutes/durationMinutes. Main stage advances only on completed attendance. Half-finished, interrupted or canceled actions do not count. Watch creates no actions: two genuine observed relevant completions permit a story to be kept. One resident can use real read/rest follow-up; two residents can use actual social exchange. No invented visual approach/path is claimed by this backend; renderer may present actual action movement.

A complication is optional and requires an actual committed post-begin household life/cancellation/interruption event. No dinner burn, appliance break, fire, outage or sandwiches are invented for drama. Real repairs/fire response are offered only when the corresponding actual condition exists. Quiet/music adaptation is earned only once the alternate real activity finishes; the story does not claim the broken object was fixed merely because the plan changed. Retry dinner re-plans from actual current food and object state.

Finish requires reflecting stage and at least two actual attended completions. The earned keepsake is a bounded story-card record, anchored to a real used object when available. It does not create a purchased furniture object or phantom photo. keepsake includes id,title,text,minute,actual participating personIds,anchorObjectId,sourceActionIds and actual complication source. Canonical life memories (when present), actual shared pair memories (when a canonical tie exists), and HOUSE_EVENING_KEEPSAKE event retain the genuine source. A resident who was away and did not participate is not credited. UI/renderer may display the card at its anchor and call recall to show its actual story.

One active episode, eight keepsakes, 32 receipts, 48 events, 24 completion evidence rows, 12 pending actions and bounded per-person completion highwaters. State is validated at most 48 KiB. No private timers. Duplicate end-minute hooks/commands/completions cannot grant a second keepsake or re-count attendance. Profile metadata lives in existing canonical profile/Social stores rather than a second resident registry.

Additional optional controls: choose IDs change-quiet/change-cook/change-music/observe change only the plan and leave actual activity progress untouched. Inspector active.changeApproaches[] exposes these. cancel closes the optional scenario with no keepsake and cancels no underlying activity. This prevents an initially unaffordable/broken plan from trapping the user; adaptation/recovery does not require inventing an interruption.

A completed real joke unlocks active.followups[]: keep-joking, ask-hobbies, admit-terrible. Send them through choose. They run actual 15-minute joke/interests/apology actions with the original actual pair and sourceActionId provenance. They do not skip elapsed time or invent instant laughter. Follow-up completion records followupOfActionId. active.done distinguishes closed/remembered scenarios; available options carry real admission reasons.

Same-minute events that already existed when begin was pressed are snapshotted as known, so an old breakage cannot masquerade as a new evening complication. Actual repair/fire completion may set complication.resolvedByActionId only after the canonical condition is actually cleared. Adapted plans separately store adaptedByActionId after the real replacement activity completes.

Latest targeted validation: 15 evening tests pass, 107 assertions. A broader real household/Social/roommate regression run passed 47 tests, 357 assertions before these final optional-plan and source-baseline refinements. No UI, app, installer, model or renderer file was edited by this component.

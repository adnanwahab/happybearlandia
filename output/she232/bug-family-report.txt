CONFIRMED BUGS

B1 / high / inconsistent URL canonicalization bypasses server source denial
Evidence: server.js:552-563, especially line 562, and serveStatic at 205-224.
The explicit deny rules use decodedWorldPath, but the generic /api.js and
-api.js suffix guard uses raw pathname. Static serving then decodes it.
Reproduction: execute the actual extracted static helper and World gate against
local files, without opening a socket. /world/api.js -> 404;
/world/%61pi.js -> 200; /world/city/api.js -> 404;
/world/city/%61pi.js -> 200. No source response bodies were printed.
Root cause: authorization/filtering and file resolution use different forms of
one path. This exposes code explicitly marked server-only; it does not establish
credential disclosure or arbitrary files outside the static root.
Family search: explicit decoded denies for Decision, AI, temporal and share
stores resist this particular encoding. Generic suffix denies across other
World modules share the defect. Tools/data/game static trees use containment
checks; their public serving is not itself proof of a bug. Symlink escape and
other unpublished server modules remain untested risks.
Fix: canonicalize once before all deny/allow checks; resolve the same canonical
path. Prefer a reviewed browser-public allowlist over expanding ad hoc denies.
Acceptance: plain, encoded letter, encoded suffix and encoded separator variants
all deny server modules while browser modules and normal routes still work.

B2 / medium / worker dispatch exceptions leak resources beyond disposal
Evidence: world/constitution-city/runtime.js:12-26, 30-33, 46-47.
Reproduction: inject a worker whose postMessage throws 'dispatch failed', with a
valid three-household initial city and normalized checked-in Dear Congress plan;
one current scenario, one run, month 0. run() rejects, but worker terminations=0,
abort listeners added=1/removed=0. destroy() leaves the same counts.
Root cause: Promise-executor rejection bypasses cleanup. The task is assigned
to catalog only after request returns; run's finally clears catalog without
terminating it, so destroy cannot reach the leaked task.
Family search: Reality runtime catches postMessage; City worker-call has
explicit construction/dispatch/deadline coverage; House checkpoint catches it;
law comparison also catches it. Bakery pending map and House Studio pending map
have unguarded dispatch patterns: probable risks, not independently reproduced
leaks in their actual browser routes. Research catches startup but its block-
scoped worker is not available to catch for cleanup: probable same-family risk.
Fix: one idempotent finish path covering dispatch, error, result and abort;
clear handlers/listeners and terminate exactly once. Preserve Constitution's
intentional partial-catalog cancellation semantics.
Acceptance: thrown dispatch releases worker/listener, retry works, destroy is
idempotent, and existing partial cancellation and replay supersession still pass.

B3 / medium / malformed successful responses silently become valid client data
Evidence: world/decision/client.js:5-12 and 22-31.
Reproduction: inject HTTP 200 with '<html>fallback</html>'; results('demo')
resolves {}. A watcher can forward it to onUpdate and continue polling rather
than signal a malformed-response error.
Root cause: JSON parsing errors are swallowed before HTTP success is checked.
Family search: every Decision client method shares request(). Exploration and
Reality share loading parse explicitly instead. world/render.js:1986 catches
JSON to null in a different call path; do not classify it without its caller's
error contract. That occurrence alone is not a confirmed same-family defect.
Fix: reject malformed successful JSON with actionable API error; retain useful
HTTP errors when error bodies are not JSON. Validate response envelopes at the
boundary rather than manufacture an empty object.
Acceptance: malformed 2xx calls onError once, never onUpdate, stops polling;
valid results and existing summary/full-trace behavior stay compatible.

PROBABLE RISKS (not counted as reproduced user defects)

R1 / medium / stale optimization or fork UI responses
world/decision/exploration.js:93-96,125-133,157: job/fork results are assigned
after awaits without the generation/identity checks used by trace cache and
studio. pollJob checks destruction but not that the response matches the
currently selected job. Verify delayed old poll versus replacement job and an
experiment switch during fork before repair. Bind responses to source experiment,
job and generation; never promote a stale result into a new scenario.

R2 / medium / incomplete bounded worker recovery
Reality runtime has cancel/error handling but no deadline or messageerror
handling; Timeline Braids constructs/posts outside a recovery try block and may
leave 'Reading saved checkpoints…' after synchronous failure. Related unguarded
dispatch cases are listed in B2. Missing timeout alone does not prove a hang.
Fault-inject stalled startup, malformed messages and unavailable Worker at normal
entry points; reuse the established City worker-call lifecycle contract where
compatible. Coordinate with SHE-108 instead of duplicating its implementation.

R3 / low / catalog documentation and manually curated directory drift
world/universe/README.md still describes 29 originals; registry and its current
test intentionally contain 31 after map/flagship additions. routes.html has its
own curated cards and derives its visible live count from those cards. This is
not evidence of a live 29-versus-31 counter bug. Clarify curated scope and update
documentation; test membership only if product requires catalog parity.
